# Webツール開発要件定義書

## 1. プロジェクト概要
**名称**: 評価調書ハック・エージェント（Tax Audit Recon Tool）
**目的**: 「元データ（今年度データ）」と「過去のファイル（比較対象）」を照合し、課税評価額の差異や特例適用の漏れを効率的に発見・精査する。

## 2. データ入出力要件
### 2.1 入力データ
1.  **元データ（Master Data）**
    *   形式: CSV
    *   内容: 今年度の課税データ。
    *   構造: 1行1納税者。資産種類（1〜7）が横並び（列）に配置されている「横持ち」データ。
    *   必須項目: 課税区コード, 宛名番号, 各種類の取得価額・評価額・決定価格・課税標準額など。
    *   **柔軟性**: ファイル名が`元データ.csv`に限らず、任意のファイル名で取り込めること。

2.  **比較対象データ（Target Data / Past Data）**
    *   形式: CSV（またはExcelから変換したもの）
    *   入力方法: **ドラッグ＆ドロップ**（ファイル名に依存しない）。
    *   用途: 昨年度データや、紙の申告書データとの突合用。

### 2.2 出力データ
*   **疑義リスト（Review List）**: 精査フラグ（赤字、保留）が付いたレコードのみを抽出したCSV。
*   **保存形式**: ブラウザの`localStorage`を使用し、作業進捗（チェック済み、メモ、ステータス）を永続化。

## 3. 機能要件

### 3.1 前処理・データ変換
*   **名称変換**: 課税区コード（例：0, 10...）を名称（鶴見, 神奈川...）に自動変換。
*   **データ構造変換（Unpivoting）**:
    *   入力の「横持ち（種類1〜7が列）」を、UI表示用に「縦持ち（納税者1人につき種類1〜7の行＋合計行）」に展開。
    *   これにより、種類ごとの詳細比較を容易にする。

### 3.2 照合・差分抽出ロジック（Comparison Logic）
*   **キー**: `宛名番号`
*   **完全一致判定（Auto-Verify）**:
    *   「宛名番号」＋「各資産種類（1〜7）の全数値項目（取得・評価・決定・課税・件数）」が一致する場合、**「作業済み（Verified）」**として初期表示で除外またはグレーアウト。
    *   ハッシュ値などを用いて高速かつ堅牢に判定。
*   **2,000円差異アラート**:
    *   条件: $\text{評価額合計} - \text{課税標準額合計} \ge 2,000$
    *   アクション: 該当箇所の背景を**黄色**で強調（特例適用漏れや計算ミスの疑い）。

### 3.3 UI/UX（スマート・ビューイング）
*   **リスト/カード表示**:
    *   一覧性重視のテーブル表示と、詳細確認用の「1画面1納税者」カード表示を切り替え可能。
    *   視線移動を最小化するデザイン。
*   **インタラクティブ操作**:
    *   **トグル判定**: 各項目をクリックで「✅ 一致（緑）」「⚠️ 差異あり（赤）」に切り替え。
    *   **進捗管理**: 宛名ごとに「完了」「保留（疑義あり）」ステータスを変更可能。
*   **ドラッグ＆ドロップ実装**:
    *   画面上のドロップエリアにファイルを放り込むだけで比較開始。

## 4. 非機能要件
*   **セキュリティ**: サーバーレス動作。全処理をブラウザ（JavaScript/Wasm）内で完結させ、外部にデータを送信しない。
*   **永続性**: F5リロードしても作業内容が消えない（LocalStorage）。
*   **デザイン**:
    *   モダンでプレミアムなUI（Tailwind CSS）。
    *   ダークモード対応。
    *   スムーズなマイクロインタラクション。

## 5. 技術スタック（推奨）
*   **Framework**: Vite + React (高速かつ堅牢なSPA構築のため)
*   **Styling**: Tailwind CSS (指定の要件に準拠)
*   **State Management**: React Context + LocalStorage custom hooks
*   **Parsing**: PapaParse (CSV処理)
