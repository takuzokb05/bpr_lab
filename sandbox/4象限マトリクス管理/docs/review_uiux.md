## 総評（3行以内）

4象限という情報構造は機能しているが、ラベルの階層（アイコン+和文/英文混在）と Survival モードの独自世界観が「記憶に残るプロダクト」と「認知負荷の高いUI」の境界線上にある。Critical な論点は 2 つ — ドラッグ＆ドロップがキーボード操作で代替できずアクセシビリティが完全に欠落している点、および textarea 編集ごとに `renderAll()` を呼んで履歴ノードを張り替えているため入力フォーカスと IME が壊れる潜在バグがある点。Survivalモードのカウントダウン・ネオン演出は強力だが、抜け出し経路の表記（`ABORT MODE` / 英語）と編集中タスクの消失リスクに手当てが必要。

## Good（残すべき強み）

- **4象限の色分けが一貫している**（`タスク管理.html:10-13`）。`--q1-bg` 〜 `--q4-bg` の淡色背景＋ `--q1-border` 〜 `--q4-border` の濃色ボーダーで、象限と所属カードの紐付きが視覚的に追える（`タスク管理.html:126-129` でカードの左ボーダー色を象限ごとに継承）。
- **「消す」と「終わる」を分離**したコピーと情報アーキテクチャ（`タスク管理.html:437`）。削除/完了/詳細の3アクションが Icon-btn で色分けされ（`タスク管理.html:183-187`）、完了パネルは右スライドアウトで独立レイヤ化されている（`タスク管理.html:256-271`）。タスクマネージャーで頻出する混同を意識的に分離している点は残すべき。
- **Undo トースト**（`タスク管理.html:302-319`, `1059-1068`）で 5 秒以内の取り消しが可能。削除の心理的コスト低減として効いている。
- **締切バッジの状態遷移**（`タスク管理.html:558-564`）が `overdue` / `today` / `due` / `none` の4状態で色分けされ、一目でプレッシャーが伝わる。
- **履歴（activityLog）を最大30件保持**（`タスク管理.html:586`）し、移動・締切更新・完了/取消しを時系列で追える。振り返り学習に寄与する設計。
- **v5→v6 マイグレーション**（`タスク管理.html:608-637`）で既存ユーザーのデータを保全しつつ zone スキーマを刷新している点は堅実。
- **touch-action: none による操作領域の明示**（`タスク管理.html:124`）でモバイルでのスクロール衝突を回避。
- **Intl.DateTimeFormat 'ja-JP'** を使った日時整形（`タスク管理.html:537-540`）。和暦ロケールでゼロ埋めされたフォーマットが落ち着いた印象を与える。

## Improvement Opportunities（中期）

- **象限カウントの「件」表記**（`タスク管理.html:698`）: `3件` / `12件` と数字に単位を付けているが、象限によっては2桁・3桁で右側にはみ出る。`q-count` にも `aria-label="タスク3件"` を付与し、視覚的には数字を大きめ・単位を小さめに。
- **sticky な `.q-title`**（`タスク管理.html:99-104`）: `background: inherit` で sticky 化しているが、象限背景が単色のため下にスクロールしたカードが透けて見えない。意図通り動くが、カードの影が被ると見切れる。`backdrop-filter: blur(4px)` でもう一段読みやすくできる。
- **並び順が「締切昇順 → 更新新しい順」固定**（`タスク管理.html:678-685`）: 優先度（Q1/Q2）順やカード上での手動並び替えができない。Q1内で「どれから手をつける？」をドラッグでユーザーが決めたいケースに応えられていない。象限内のD&Dで `order` 永続化を入れると意思決定が速くなる。
- **SURVIVAL モードの時刻入力**（`タスク管理.html:477`, `1238-1272`）: `target-time` は単一時刻のみで、日付跨ぎ（深夜 2:00 締切）を扱えない。`diff < 0` で即 `00:00` 固定（`タスク管理.html:1244-1248`）なため、朝9時に「目標 18:00」と入れるつもりが過去の時刻を誤って入れると何も警告なく 0 表示で固まる。
- **タスク追加時のデフォルト象限が q4**（`タスク管理.html:1012, 1015`）: 多くのユーザーは「今頭にあるタスク」を入れるとき重要度を後から振るため、q4（非重要・非緊急）に沈められる設計は機能的には正しいが、UI上「UNSORTED」と再ラベルしている q4 の役割が兼務しており、本当に非重要なタスクと未仕分けが混在する。「INBOX 専用レーン」を 5 つ目として分けるか、`q4` のラベルを「UNSORTED（未仕分け）」単独に寄せる（現状は `タスク管理.html:450` で2つの意味を併記）。
- **カード展開状態が非永続**（`タスク管理.html:867-870`）: `classList.toggle('expanded')` のみでタスクオブジェクトに保存されない。`renderAll()` のたび畳まれる。`task.__expanded` を volatile メモリで持ち、再描画後にフォーカスと一緒に復元するとC2の副症状も緩和される。
- **ネオンの `text-shadow: 0 0 20px`**（`タスク管理.html:356`）: 大サイズ数字にグローを付けているがコントラスト比が背景 #0a0a0a に対して白文字4.5:1 は満たす。一方 critical 時の `--neon-red #ff003c` × 黒背景は WCAG AAA 基準では視認性ギリギリ。15分以下で赤に切り替わる演出は「煽る」意図は成功しているが、色弱ユーザーに対し文字サイズの増大やアイコン追加（⏱️ の脈動など）で冗長化するとよい。

## Nice to Have（余裕があれば）

- タスク件数が **100件を超えたときの仮想化**。`renderActiveZones` は全カードを毎回 DOM 再構築するため（`タスク管理.html:910-940`）、100件を超えると描画コストが顕在化する。IntersectionObserver 仮想化か、少なくとも `renderAll` を debounce する。
- **長文タイトル**: `.card-title` の `max-height: 180px`（`タスク管理.html:166`）で内部スクロールにはなるが、`q-count` と合わせた象限内スクロールで「どこに何件あるか」の視認がしづらい。150文字以上は自動で省略表示にし、展開時のみ全文を見せる。
- **アクティビティログ 30件上限**（`タスク管理.html:586`）で肥大を抑えているのは良い。ただし `unshift` で新しい順に保存しているため、30件を超えると古い履歴が順次消える。完了タスクでは履歴こそが価値なので、`completed` 後は無制限保存に切り替える／完了パネル内でのみ全件表示する、といった差別化があるとよい。
- **Survival のスロット上限**: MUST/SHOULD に複数カードを投入できてしまう（UI上は `slot-must` にドロップし放題）。「MUST は1〜2件に絞る」というコピー（`タスク管理.html:926`）はあるが制約は効いていない。3件目をドロップしたら警告、または自動で survival-picker に押し戻すと「絞り込む」という設計意図が生きる。
- **キーボードショートカット**: `N` で新規、`Esc` で完了パネル閉じ、`Ctrl+Z` で undo があればパワーユーザーが定着する。現状は全てマウス駆動。
- **色覚多様性対応**: Q1/Q3 の赤/黄色は P 型色覚で区別が弱い。左ボーダーの太さ・パターン（実線/点線/二重線）で冗長化する。
- **タスク追加時の象限選択**: 現状ボタン1つで q4 に追加するだけだが、ヘッダから直接「Q1に追加」などのドロップダウンがあれば、「今これヤバい」を即入力できる。

## モバイル特有の論点

- **象限縦積み（<=880px）**（`タスク管理.html:422-424`）: `grid-template-rows: repeat(4, minmax(0, 1fr))` で均等4分割。画面全高を4象限が奪い合うため、1象限に見えるのは 1〜2 枚。カード3枚以上は内部スクロールになるが、外側のページスクロールと衝突する（`body { overflow: hidden }` で外側は固定されているので衝突自体は起きないが、スワイプで象限間を行き来する導線がなく、各象限の小窓を個別に縦スクロールする忙しさが出る）。提案: `minmax(200px, auto)` にしてページ全体を縦スクロールさせる／または象限を「スワイプ切替タブ」に変える。
- **タッチターゲット**: `.icon-btn` は実測 30px 前後で WCAG AAA（44×44）を満たさない（`タスク管理.html:175-182`）。指が太いユーザーや電車内で誤タップが増える。モバイルブレークポイント（<=640px）で `.icon-btn { padding: 10px 14px; min-height: 44px }` を推奨。
- **ヘッダボタン3個が横並び → <=640px で縦積みではなく stretch**（`タスク管理.html:425-430`）: `.header-actions button { flex: 1 }` で横に3等分。幅 375px (iPhone SE) だと各ボタン 110px 強で「⚠️ SURVIVAL」が折り返す可能性。`flex-wrap` は効いているが、SURVIVAL だけ2行になると視覚的ノイズ。
- **`user-scalable=no`**（`タスク管理.html:6`）: ピンチズームで拡大できない。`.card-title` のフォントサイズ `1rem` と `.q-title` の `.82rem` が読みにくい人に対し、逃げ道がない。Safari は iOS 10 以降これを無視するが、Android Chrome では効く。
- **D&D の長押し発火**: `pointerdown` 即ドラッグ（`タスク管理.html:866`）。タップとドラッグが区別されない。`click` イベントも別個に登録されているため（`タスク管理.html:867-870`）、タップで expand 展開したいのに小さく動いてしまうとドラッグ扱いになる。150ms の長押し閾値または 8px の移動閾値を入れると誤操作が減る。
- **Survival の `timer-display font-size: min(18vw, 120px)`**（`タスク管理.html:351`）: 縦長スマホだと 18vw = 約70px で適度。ただしランドスケープ回転時に幅が広がり 120px に貼り付いて、上下のスロットが画面外に出る恐れ。
- **完了パネル `width: min(440px, 100vw)`**（`タスク管理.html:260`）: <=640px で全画面（`タスク管理.html:429`）。ただし閉じるボタン「閉じる」（`タスク管理.html:459`）のみが終了導線。iOS の「戻るスワイプ」ジェスチャに非対応なのでフルスクリーン化すると脱出感が弱い。左端からのスワイプでパネルを閉じる操作を入れると良い。
- **vibrate API**（`タスク管理.html:1028, 1040, 1052, 1079, 1091`）: iOS Safari は `navigator.vibrate` 非対応。Android のみで動く。触覚フィードバックで差別感が出ているが、iOS ユーザーには「何の手応えもない」UX になる。視覚フィードバック（カードが pulse する）で冗長化すると両 OS で体験を揃えられる。
