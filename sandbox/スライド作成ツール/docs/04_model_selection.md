# Q4: 各処理工程に最適な API モデルの比較選定

## 分析対象

Q1〜Q3 の調査結果を踏まえ、スライド作成ツールの各処理工程に最適な AI モデルを選定する。

## 処理工程と選定結果

### 工程一覧

| 工程 | 内容 | 選定モデル | モデルID | 理由 |
|------|------|-----------|---------|------|
| **PDF 解析** | 資料を読み取り構造化 | **Gemini 3 Flash** | `gemini-3-flash-preview` | 無料枠あり、1M コンテキスト、PDF理解力最高 |
| **スライド構成生成** | 構成 JSON を生成 | **Gemini 3 Flash** | `gemini-3-flash-preview` | 構造化出力+ツール併用対応、thinking設定可能 |
| **背景画像プロンプト生成** | 各スライドの画像プロンプト | **Gemini 3 Flash** | `gemini-3-flash-preview` | 構成生成と同時に出力可能 |
| **背景画像生成** | 画像を生成 | **Nano Banana Pro** | `gemini-3-pro-image-preview` | 4K対応、16:9、高品質テキスト描画 |
| **テキスト配置最適化** | テキスト位置・サイズ決定 | **不要（ルールベース）** | — | 下記で詳述 |
| **1枚リライト** | 特定スライドの再生成 | Gemini 3 Flash + Nano Banana Pro | 同上 | 構成再生成 + 画像再生成 |

### テキスト配置最適化について（重要な判断）

**結論: AI による動的なテキスト配置最適化は不要。ルールベースで十分。**

**根拠**:

1. **python-pptx の制約**: テキストボックスは座標指定で自由配置可能だが、背景画像の内容を「認識」してテキスト位置を動的に調整する必要性は低い
2. **背景画像のプロンプト制御**: 背景画像を生成する時点で「テキスト用の余白を確保」するプロンプトを入れることで、テキストとの干渉を回避できる
3. **テンプレート方式が実用的**: スライドの種類（タイトル、箇条書き、図表）ごとに固定レイアウトテンプレートを用意し、テキスト位置を決め打ちにする方が安定的
4. **コスト・複雑性**: AI でテキスト配置を最適化するには画像認識 + 座標計算が必要で、実装コストに見合わない

**提案レイアウトテンプレート**:

```
[タイトルスライド]
┌──────────────────────┐
│                      │
│    [タイトル]         │  ← 中央、大きめフォント
│    [サブタイトル]      │  ← 中央、小さめフォント
│                      │
└──────────────────────┘

[コンテンツスライド]
┌──────────────────────┐
│ [タイトル]            │  ← 上部、左寄せ
│ ───────────────────── │
│ • ポイント1           │  ← 左寄せ、箇条書き
│ • ポイント2           │
│ • ポイント3           │
│                      │
└──────────────────────┘

[セクション区切り]
┌──────────────────────┐
│                      │
│                      │
│    [セクション名]     │  ← 中央、大フォント
│                      │
│                      │
└──────────────────────┘
```

## 詳細比較

### PDF 解析モデルの比較

| モデル | 品質 | コスト | 速度 | 判定 |
|--------|------|--------|------|------|
| **Gemini 3 Flash** | ◎+ | 無料枠あり（有料: $0.50/1M tok） | 高速 | **← 採用** |
| Gemini 2.5 Flash | ◎ | 無料枠あり（有料: $0.30/1M tok） | 高速 | 2026/6/17 廃止予定 |
| Gemini 2.5 Pro | ◎ | $1.25/1M tok | 低速 | コスト過剰 |

**判断**: Gemini 3 Flash。Pro 級の知能を Flash の速度・コストで提供。2.5 系は廃止予定のため最初から 3 系で構築。

### スライド構成生成モデルの比較

| モデル | 構造化出力 | 品質 | コスト | 判定 |
|--------|-----------|------|--------|------|
| **Gemini 3 Flash** | `response_schema` + ツール併用 ○ | ◎+ | 無料枠あり | **← 採用** |
| Gemini 2.5 Pro | `response_schema` ○ | ◎+ | $1.25+/1M | コスト過剰、廃止リスク |
| GPT-4o (参考) | JSON mode ○ | ◎ | $2.50/$10.00 | 別API必要、高コスト |

**判断**: Gemini 3 Flash。thinking レベル設定（low〜high）で品質と速度のトレードオフを制御可能。

### 背景画像生成モデルの比較

| モデル | モデルID | 品質 | コスト/枚 | 16:9 | 特徴 | 判定 |
|--------|---------|------|----------|------|------|------|
| **Nano Banana Pro** | `gemini-3-pro-image-preview` | ◎+ | 要確認 | ○ | 4K対応、高品質テキスト描画、thinking推論 | **← 採用** |
| Imagen 4 Fast | `imagen-4.0-fast-generate-001` | ○ | $0.02 | ○ | 最安、専用API | フォールバック候補 |
| Imagen 4 Standard | `imagen-4.0-generate-001` | ◎ | $0.04 | ○ | バランス型 | - |
| Nano Banana | `gemini-2.5-flash-image` | ○ | $0.039 | ○ | 高速、テキスト描画対応 | 2.5系、将来廃止リスク |
| DALL-E 3 (参考) | — | ◎ | $0.04〜 | ○ | 別APIキー必要 | - |

**判断**: Nano Banana Pro（Gemini 3 Pro Image）を採用。4K 出力対応、テキスト描画の精度が高く、スライド内テキストの直接レンダリングも将来的に可能。コストが高い場合は Imagen 4 Fast にフォールバック。

| 工程 | コスト |

| 背景画像生成（20枚） | $0.40（≒60円） |

| **合計** | **$0.50（≒75円）** |

### 月間利用（週3回 × 20枚）

| 項目 | コスト |
|------|--------|
| テキスト処理 | 無料 |
| 画像生成（12回 × 20枚 = 240枚） | $4.80（≒720円） |

## 総合評価

### 強み

- **API 一本化**: Gemini API キー1つで全工程をカバー（テキスト処理 + 画像生成）
- **無料枠の活用**: テキスト処理は全て無料枠内で完結
- **シンプルなアーキテクチャ**: `google-genai` SDK 1つで完結。追加ライブラリ不要
- **テキスト配置のルールベース化**: AI 依存を減らし、安定性と速度を向上

### リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| Gemini 3 Flash の無料枠廃止 | 中 | 有料でも $0.50/1M tok。月数百円程度 |
| Nano Banana Pro の価格確定・改定 | 中 | Imagen 4 Fast（$0.02/枚）にフォールバック可能 |
| python-pptx の XML ワークアラウンド破壊 | 低 | python-pptx はバージョンアップ頻度が低い。1.0.2 で安定 |
| 背景画像の品質ばらつき | 中 | プロンプトテンプレートを精査。不満なら Imagen 4 Standard に昇格 |

### ギャップ分析

- **触れられていないが重要**: Gemini API の日本語プロンプトの品質。英語と日本語で構成生成の品質差があるか要検証
- **Phase B で検証すべき**: `response_schema` で実際にスライド構成 JSON を安定的に生成できるかのプロトタイプ検証
