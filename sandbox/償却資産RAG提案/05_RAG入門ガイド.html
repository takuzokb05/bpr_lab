Section 01

NotebookLMの裏側で何が起きているか

NotebookLMにPDFを入れて質問すると、答えが返ってきます。
あの一連の流れの中で、実は3つのステップが自動で動いています。

NotebookLMの処理フロー
PDF をアップロード → 文書を小さく分割して保存 → 質問に近い部分だけ探す → 見つけた部分をもとにAIが回答

この「分割 → 検索 → 回答生成」の仕組みを、技術用語で RAG （Retrieval-Augmented Generation = 検索で補強した文章生成） と呼びます。

つまり、AIが「全部のPDFを丸ごと暗記している」のではなく、質問のたびに関連しそうな箇所を探し出して、その部分だけを読んで答えているのです。

たとえるなら：百科事典を丸暗記した人ではなく、「質問を聞いて、索引を引いて、該当ページを開いてから答える人」です。索引の引き方や、ページの切り分け方で、答えの質が変わります。
Section 02

チャンク分割とは

RAGの最初のステップが チャンク分割 （文書を小さなかたまりに切ること） です。

たとえば100ページのPDFがあるとき、まるごと1つのかたまりとして扱うと、検索で見つけたい箇所がぼやけてしまいます。逆に1文ずつバラバラにすると、文脈がなくなって意味が通じません。

文脈がなくなる

切り方で精度が変わるというのが大事なポイントです。NotebookLMではこの分割を自動でやってくれますが、自分たちでRAGシステムを組む場合は「どう切るか」を設計する必要があります。

NotebookLMの場合：アップロード時に自動でチャンク分割されます。私たちは意識しなくて済みますが、裏では必ずこの処理が走っています。
Section 03

ベクトル検索（埋め込み）とは

チャンクに分割したあと、次は「質問に近いチャンクを探す」ステップです。
ここで使われるのが ベクトル検索 （意味の近さで探す検索） です。

普通の検索との違い

キーワード検索（従来型）

「償却資産」で検索 → 「償却資産」という文字列が含まれる箇所だけヒット

「固定資産の減価」「設備の価値減少」など、同じ意味でも別の言葉で書かれていると見逃す

ベクトル検索（意味ベース）

「償却資産」で検索 → 意味が近い箇所をまとめてヒット

「固定資産の減価」「設備の価値減少」も意味が近いので見つかる

なぜ「意味」で探せるのか

文章を数百個の数字の列（これをベクトル = 数字の羅列）に変換します。意味が近い文章は、似た数字の列になります。

ベクトル化のイメージ
「償却資産の申告」 → [0.82, 0.15, 0.91, ...]
「固定資産の届出」 → [0.80, 0.17, 0.89, ...] ← 数字が近い = 意味が近い
「今日の天気予報」 → [0.12, 0.95, 0.03, ...] ← 数字が遠い = 意味が遠い

質問文もベクトルに変換して、数字の列が一番近いチャンクを上位から取り出します。これがベクトル検索です。

イメージ：図書館で本を探すとき、タイトルの完全一致で探すのがキーワード検索。「この本に近い内容の本はどれ？」と司書さんに聞くのがベクトル検索です。
Section 04

なぜ精度が出ないことがあるか

NotebookLMやRAGシステムで「ちゃんと答えてくれない」ことがあります。
原因はだいたい3つに分かれます。

原因 1：チャンクの切り方が合っていない

重要な情報が2つのチャンクにまたがって切れていると、どちらのチャンクにも中途半端な情報しかなく、正しい回答が作れません。

チャンクまたぎの例
「償却資産の申告期限は...」
ここで切れる
「...毎年1月31日です。」

「申告期限はいつ？」と聞いても、どちらのチャンクにも完全な答えがない

原因 2：質問の仕方があいまい

質問があいまいだと、ベクトル検索で的外れなチャンクを拾ってしまいます。

あいまいな質問

「資産の申告ってどうやるの？」

具体的な質問

「償却資産の1月申告の対象となる資産の種類は？」

原因 3：ソース文書の品質が低い

元のPDFがスキャン画像だけでテキストがない、表がレイアウト崩れしている、同じ内容が複数のファイルにバラバラに書かれている、といった問題があると精度が下がります。

覚えておきたいこと：RAGの精度は「AIの賢さ」だけでは決まりません。ソースの品質 × 分割の適切さ × 質問の明確さの掛け算です。どれか1つが低いと、全体の精度が落ちます。
Section 05

PoCで気をつけること

ソースの前処理

  • スキャンPDFはOCR（文字認識）を通してテキスト化する
  • 表形式のデータは、表だとわかるように整形しておく
  • 複数の文書に同じ内容がある場合は、最新版に統一する
  • 不要なヘッダー・フッター・ページ番号などのノイズを除去する

質問のコツ

  • 具体的に聞く（「いつ」「何を」「どの条件で」を明示する）
  • 1つの質問に1つのテーマ（複合的な質問は分ける）
  • 回答に使われたソース（引用元）を確認する癖をつける

精度の測り方

「なんとなく良い」「なんとなくダメ」では改善できません。以下の手順で定量的に測ります。

精度検証の手順
1 あらかじめ「正解」がわかっている質問を20〜30個用意する
2 RAGに質問して、回答を記録する
3 正解と照らし合わせて、正答率を出す
4 間違いのパターンを分析して改善する
よくある落とし穴：PoCで「答えが出た」ことに満足してしまい、「その答えは正しいか」の検証を飛ばすケースがあります。RAGは自信満々に間違える（ハルシネーション = AIのもっともらしい嘘）ことがあるので、必ず正解との照合が必要です。
Section 06

NotebookLMとGeminiの使い分け

どちらもGoogleのAIですが、得意なことが違います。

NotebookLM Gemini
しくみ アップロードした文書の中だけを検索して回答（RAG） 学習済みの一般知識 + ネット検索で回答
得意なこと 「この文書に何が書いてある？」
= 知識ベースとして使う		 「文章を要約して」「表を作って」
= タスク実行に使う
回答の根拠 アップロードした文書（出典が明確） 一般知識（出典があいまいなことも）
向いている場面 法令・規程・マニュアルへの問い合わせ 下書き作成、ブレスト、一般的な調査
注意点 文書にない情報は答えられない 古い情報や不正確な情報が混じることがある
使い分けの判断フロー
「この資料の中から情報を探したい」 → NotebookLM
「一般的な知識をもとに作業してほしい」 → Gemini
「資料の内容を踏まえて文章を作成してほしい」 → NotebookLM で情報抽出 → Gemini で文章作成
PoCとの関係：償却資産の問い合わせ対応にRAGを使うなら、NotebookLMのようなしくみが基本になります。Geminiは一般知識で答えるので、自治体固有の規程やルールには対応できません。「自分たちの文書をもとに、正確に答える」にはRAGが必要です。
GLOSSARY

7. デジタル統括本部との打ち合わせで出てくる用語

デジタル統括本部のメンバーはデジタル職が多く、以下の用語を当たり前に使います。全部覚える必要はありませんが、打ち合わせで出てきた時に「何の話をしているか」がわかることが大事です。

用語 意味 打ち合わせでの使われ方
PoC
ピーオーシー		 Proof of Concept。「本当にうまくいくか」を小さく試す実験のこと。 「まずPoCで精度を見ましょう」「PoC期間は1〜2ヶ月で」
SaaS
サース		 Software as a Service。インターネット経由で使える既製サービス（例: NotebookLM、kopo）。 「SaaSでいくか自前構築か」「SaaSなら運用が楽」
オンプレ
オンプレミス		 庁内のサーバーにシステムを置いて動かす方式。クラウドの反対。 「セキュリティ的にオンプレですか？」「オンプレだとコスト上がります」
エンベディング
埋め込み表現		 文章を数値（ベクトル）に変換すること。セクション3で解説した「意味で検索する」ための前処理。 「エンベディングモデル何使います？」「エンベディングの精度が鍵」
ハルシネーション
幻覚		 AIがもっともらしいウソをつくこと。ソースにない情報をでっち上げてしまう現象。 「ハルシネーション対策どうします？」「免責表示で対応」
プロンプト AIへの質問文・指示文のこと。聞き方で回答の質が大きく変わる。 「プロンプトを工夫すれば精度上がるかも」「プロンプトテンプレート作りましょう」
トークン AIが文章を処理する最小単位（だいたい日本語1文字＝1〜2トークン）。量が多いと処理が遅く・高くなる。 「トークン数の上限に引っかかってますね」「コストはトークン単価×量です」
API
エーピーアイ		 プログラムからサービスを呼び出す窓口。GeminiのAPIを使えば、画面を触らずに大量処理できる。 「API経由で自動化できます」「APIキーの管理が必要」
RAG
ラグ		 Retrieval-Augmented Generation。自分たちの資料を検索してからAIが回答する仕組み（本ガイドの主題）。 「RAGで評価要領を検索させましょう」「RAGの精度はソースの質次第」
ファインチューニング AIモデル自体を自分たちのデータで追加学習させること。RAGとは別のアプローチで、コストが高い。 「ファインチューニングは不要、RAGで十分です」（この回答ができれば上出来）
コツ：全部覚えようとしなくて大丈夫です。わからない用語が出たら「それは○○のことですか？」と聞き返せばOK。デジタル職の方も、業務側の用語（評価要領、家屋疑義、宛名番号等）はわからないので、お互い様です。
