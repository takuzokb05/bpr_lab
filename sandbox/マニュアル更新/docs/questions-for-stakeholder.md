# 相談者に聞くべき質問リスト

## 目的
提案書の「Why」を深掘りし、焦点を絞るための質問。
しつこくても構わない。表面的な「やりたいこと」ではなく、その裏にある動機・危機感・政治的文脈を引き出す。

---

## 第1層: 何が起きているのか（事実）

1. 指定管理者の事務所は全部で何箇所ありますか？ 職員数は？
2. マニュアルは何ページ・何章くらいですか？ 最後に大きく改訂したのはいつですか？
3. 事務所から市への電話問い合わせは、月にだいたい何件くらいですか？
4. 「解釈がばらついた」具体的なエピソードを2〜3つ教えてもらえますか？
5. そのばらつきの結果、住民に実害が出たケースはありますか？（クレーム、損害、訴訟等）

## 第2層: なぜそれが問題なのか（動機）

6. レベル感の統一がなぜ今必要なんですか？ 今まではそれで回っていたのでは？
7. **何かきっかけがあったんですか？** — 事故、監査指摘、住民からのクレーム、議会での質問、上司からの指示…
8. ばらつきが放置されると、最悪のシナリオは何ですか？
9. 逆に、ばらつきが「現場の柔軟さ」として機能している面はありませんか？ 統一することで失われるものは？
10. マニュアルを年1回更新する今の体制は、なぜ年1回なんですか？ もっと頻繁にやりたいけどできないのか、年1回で十分と思っていたのか？

## 第3層: なぜAIなのか（手段の選択）

11. マニュアル自体をもっと明確に書き直す、という選択肢は検討しましたか？ それではダメな理由は？
12. 定期的な研修・勉強会で統一する、というやり方はどうですか？ やったことはありますか？
13. 事務所からの問い合わせ窓口を電話以外（メール、チャット等）に広げるだけでは不十分ですか？
14. この構想（AIハブ）のアイデアは、どこから来ましたか？ 誰かに勧められた？ 他の自治体の事例を見た？
15. もしAIがなかったら、この問題をどう解決しますか？

## 第4層: 誰のための提案か（政治的文脈）

16. この構想は誰のイニシアチブですか？ あなた個人？ 上司？ 部署の方針？
17. この提案を通す相手は誰ですか？ 課長？ 部長？ デジタル統括本部？
18. 予算の見通しはありますか？ 来年度予算に入れたい話か、まだ「こういうことできないかな」の段階か？
19. デジタル統括本部が進めているRAG実証の話は知っていますか？ あの部署と連携できる関係ですか？
20. 指定管理者との関係は現在どうですか？ 一緒に改善したいと思ってくれそうな事務所はありますか？

## 第5層: 本当に欲しいもの（核心）

21. **正直に言って、一番困っていることは何ですか？**
    - a. 事務所が勝手な判断をしていて止められない
    - b. 問題が起きたときに「市が管理していなかった」と責任を問われる
    - c. マニュアルを更新する作業が大変すぎる
    - d. 事務所との関係がうまくいっていない
    - e. 上から「DXやれ」と言われて何かやらないといけない
    - f. それ以外

22. もしこのプロジェクトが大成功したら、**1年後にどういう状態になっていますか？**
23. もしこのプロジェクトをやらなかったら、**1年後にどうなりますか？** 何か悪いことが起きますか？
24. **この提案で一番最初に証明したいことは何ですか？**

---

## なぜこれを聞く必要があるのか

提案書v1に対する3者レビューで、以下が判明した：

- **定量データがない** → 質問1〜5で事実を押さえる
- **AIでなくてもいいのでは？** → 質問11〜15で代替案を潰す（か、代替案の方がいいと気づく）
- **焦点がぼやけている** → 質問21〜24で「本当に欲しいもの」を1つに絞る

特に**質問7（きっかけ）と質問21（本当に困っていること）**が最重要。
ここに本音が出れば、提案書の全体構成が変わる可能性がある。

### 想定される本音パターンと、提案の打ち手の変化

| 本音 | 提案の重心 |
|------|-----------|
| 「事故が起きて責任を問われた」 | → リスク管理・コンプライアンスの提案にする |
| 「上からDXやれと言われた」 | → 横浜市RAG実証の延長線で説明する |
| 「マニュアル更新が大変すぎる」 | → 更新効率化の提案にする。AI Q&Aは副産物 |
| 「事務所との関係を良くしたい」 | → 技術より運用・コミュニケーション設計中心に |
| 「住民サービスの質を上げたい」 | → 住民影響の定量データを前面に |

本音が違えば、提案書のトーンも技術選定も全部変わる。
