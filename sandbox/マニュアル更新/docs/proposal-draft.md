# 提案書（ドラフト）

# 「育てるマニュアル」構想
## AIを活用した指定管理者向けマニュアルQ&A基盤の構築

---

## 1. 背景と課題

### 現状

横浜市の共用部分代行管理制度では、指定管理者事務所が日常的に多くの住民対応を行っています。
市から事務所へマニュアルを**年1回更新して送付**し、これに基づいて制度を運用しています。

### 3つの課題

#### 課題1: 事務所ごとの「解釈のばらつき」

マニュアルの記述だけでは判断が難しいケースがあり、事務所が**独自に解釈して対応**してしまうことがあります。
結果として、市が意図したルールと実際の運用にギャップが生じています。

#### 課題2: 確認したくても聞きにくい

事務所から市への確認手段は主に**電話**です。
忙しい業務の合間に電話するハードルは高く、「たぶんこうだろう」で対応するケースが生まれます。

#### 課題3: 市は問題が起きるまで気づけない

事務所がどこで困っているか、どの部分の記述がわかりにくいかを、市が把握する手段がありません。
問題が発覚するのは、住民からのクレームや事故報告が上がったときです。

### 構造的な原因

```
市がマニュアルを作る → 事務所が受け取る → 現場で解釈する → ズレが蓄積する
        ↑                                                    │
        └──── フィードバックが返ってこない ←─────────────────┘
```

現場の声が市に届くチャネルが弱いため、**マニュアルが現場の実態に追いつかない構造**が固定化しています。

---

## 2. 提案の概要

### コンセプト: マニュアルを「配るもの」から「育てるもの」へ

AIチャットボットを介して、事務所と市の間に**日常的な対話の回路**を作ります。

```
事務所                    AI                      市
  │                       │                       │
  ├─ 質問する ──────────→│                       │
  │                       ├─ マニュアルに基づき回答 │
  │                       │                       │
  │    （回答できない場合） │                       │
  │                       ├─ 市にエスカレーション →│
  │                       │                       ├─ 回答を返す
  │                       │← 回答を知識ベースに追加 ┤（市が承認）
  │                       │                       │
  │                       │   ┌ 質問ログを分析 ┐  │
  │                       │   │ どこが困る？    │→│← マニュアル改善に活用
  │                       │   │ 何が足りない？  │  │
  │                       │   └────────────────┘  │
```

### 3つの価値

| # | 価値 | 説明 |
|---|------|------|
| 1 | **即時回答** | 事務所が電話せずに、24時間いつでもマニュアルに基づいた回答を得られる |
| 2 | **可視化** | どの部分に質問が集中するか、どこで解釈が分かれるかがデータで見える |
| 3 | **継続改善** | 質問と回答の蓄積がマニュアル改善の根拠になり、制度運用の質が上がり続ける |

### 他の自治体にない独自性

既存の自治体AIチャットボットの多くは**住民向け**または**庁内職員向け**です。
本提案は**指定管理者（外部委託先）向け**という、全国的にもほとんど前例のないアプローチです。

加えて、Q&Aの蓄積がマニュアル改善に循環する**「フィードバックループ」**の仕組みは、
単なるチャットボット導入を超えた、制度運用そのものの改革です。

---

## 3. 技術的な実現可能性

### 横浜市での実証結果

横浜市は2024〜2025年にかけて、選挙管理事務においてRAG（検索拡張生成）技術を用いた
生成AI実証を行い、**約4,500ページの法令・マニュアルに基づくQ&Aで回答精度 約9割**を達成しています。

共用部分代行管理のマニュアルは選挙管理に比べて手続きが定型的であり、
**同等以上の回答精度が期待**できます。

### 全国の動向

| 事例 | 概要 | 成果 |
|------|------|------|
| 横浜市（選挙管理） | 4,500ページのPDFでRAG実証 | 回答精度 約9割 |
| 千代田区 | 庁内マニュアルをRAGに投入 | 年間22,700時間の効率化見込み |
| 埼玉県庁 | 25,000人の職員向けAI Q&A | 電話問い合わせ大幅削減 |
| 総務省ガイドブック | 庁内事務のQ&Aに生成AI活用を推奨 | — |

### ネットワーク上の位置づけ

指定管理者はLGWAN（自治体閉域網）に接続していないため、
本システムは**インターネット接続系**に配置します。

- LGWAN-ASP登録は必須ではありません
- ISMAP登録済みクラウドサービスの選定が望ましい（総務省ガイドライン準拠）
- 多要素認証・通信暗号化・監査ログ等のセキュリティ対策を実施します
- **個人情報はAIに入力しない設計**とします

## 4. 導入の進め方

技術導入の前に**現場の実態把握と関係構築**を優先する、段階的なアプローチを取ります。

### Phase 0: 現場を知る（1〜2ヶ月）

| ステップ | 内容 | 成果物 |
|---------|------|--------|
| QAの棚卸し | 事務所が受ける質問・判断パターンを洗い出す | 質問パターン一覧（50〜100件） |
| マニュアルの棚卸し | 現行マニュアルの構造と使われ方を把握 | マニュアル構造図 + 課題リスト |
| 関係づくり | 事務所との信頼関係を構築 | 協力意向の確認 |

**重要**: 事務所が独自に作っている「補足メモ」「付箋」「申し送り」は、
マニュアルと現場のギャップそのものであり、AIに何を教えるべきかの最重要情報です。

### Phase 1: 小さく試す（2〜3ヶ月）

| ステップ | 内容 | 成果物 |
|---------|------|--------|
| 体感デモ | NotebookLMでマニュアル1〜2章のQ&Aを体験 | 関係者の理解・合意 |
| 協力事務所選定 | 前向きな1〜2事務所でパイロット | パイロット事務所の確保 |
| 本番ツール検証 | 製品候補の比較検討 | 製品選定方針 |

**NotebookLMについて**:
横浜市はGoogleと提携しており、近い将来NotebookLMが利用可能になる見込みです。
PoCツールとして、マニュアルPDFを投入してQ&A体験を行います。
ただしログ取得やエスカレーション機能はないため、**体感・合意形成のツール**として割り切ります。

### Phase 2: フィードバック循環を回す（3〜6ヶ月）

| ステップ | 内容 | 成果物 |
|---------|------|--------|
| 本番システム導入 | 選定した製品で構築・運用開始 | 稼働システム |
| エスカレーション運用 | AI→市への判断依頼フローを確立 | 運用ルール |
| ログ分析・改善提案 | 質問傾向からマニュアル改善点を抽出 | 月次改善レポート |

```
AIが答えられなかった質問の流れ:

  事務所が質問 → AIが回答できない → 「不十分」ボタン
      ↓
  市の担当者に通知 → 市が回答を返す
      ↓
  市が回答を承認 → 知識ベースに追加
      ↓
  次回から同じ質問にAIが回答可能に
```

**ポイント**: マニュアル（知識ベース）の更新は**市の承認を経てから反映**します。
AIが勝手にルールを変えることはありません。

### Phase 3: 展開・定着（6ヶ月〜）

| ステップ | 内容 | 成果物 |
|---------|------|--------|
| 展開拡大 | パイロット成果をもとに他事務所へ展開 | 利用事務所の拡大 |
| 事業者交代対応 | 知識ベース引継ぎ手順の整備 | 引継ぎマニュアル |
| 年次レビュー | 回答精度の総点検、満足度調査 | 年次改善計画 |

### 全体タイムライン

```
        Phase 0          Phase 1          Phase 2          Phase 3
     現場を知る        小さく試す      循環を回す       展開・定着
    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
    │QA棚卸し   │    │NotebookLM│    │本番導入   │    │他事務所   │
    │マニュアル │ →  │協力事務所 │ →  │ログ分析   │ →  │事業者交代 │
    │関係づくり │    │製品検討   │    │改善提案   │    │年次改善   │
    └──────────┘    └──────────┘    └──────────┘    └──────────┘
      1〜2ヶ月         2〜3ヶ月         3〜6ヶ月         6ヶ月〜
```

## 5. 想定される効果

### 定量的な効果（見込み）

| 指標 | 現状 | 導入後（見込み） |
|------|------|----------------|
| 事務所→市への電話問い合わせ | 把握できていない | 50%以上削減（千代田区事例参考） |
| マニュアル更新頻度 | 年1回 | 質問蓄積に基づく随時更新 |
| 事務所の誤対応 | 発生後に発覚 | AIログから兆候を早期検知 |
| 新任スタッフの立ち上がり | ベテラン依存 | AIが24時間サポート |

### 定性的な効果

- **事務所間の知識格差の解消**: A事務所の質問で得た知見がB事務所にも共有される
- **事業者交代時の引継ぎ改善**: 知識がシステムに蓄積されるため、情報ロスが大幅に軽減
- **「聞きやすい文化」の醸成**: 電話では聞きにくいことも、AIなら気軽に質問できる
- **制度運用のパートナー関係**: 「市が作る→事務所が従う」から「共に育てる」関係へ

## 6. 技術選定の方向性

### 本番システムの候補

Phase 1で比較検討し、以下のいずれかの方向で選定します。

| 方向性 | 代表的な製品 | 特徴 | 月額目安 |
|--------|------------|------|---------|
| **A. 既製品SaaS** | OfficeBot, PKSHA ChatAgent | 運用容易。更新はファイル差替えだけ | 10〜30万円 |
| **B. クラウドRAG** | Azure OpenAI + GaiXer等 | カスタマイズ自由。構築にSI支援必要 | 10〜50万円 |
| **C. チャット連携** | LINE WORKS + AI | 現場定着しやすいUI | 5〜20万円 |

### 選定の重視ポイント

1. **更新運用の現実性**: 市の担当者（非エンジニア）がWord差替えだけで知識ベースを更新できるか
2. **外部ユーザー対応**: 指定管理者（市の外部組織）がインターネット経由でアクセスできるか
3. **事業者交代耐性**: 指定管理者が変わってもシステムと知識が引き継がれるか
4. **エスカレーション機能**: AIで解決しない質問を市へ自然にエスカレーションできるか

## 7. 留意事項

### AIの回答の位置づけ

AIの回答は**マニュアルに基づく参考情報**であり、市の公式な指示・決定ではありません。
回答画面には免責事項を表示し、判断に迷う場合は市への確認を促す設計とします。

### 個人情報の取り扱い

住民の個人情報はAIに入力しない設計とします。
質問は手続きの一般的なルール確認に限定し、特定の住民に関する判断はAIの対象外とします。

### セキュリティ

- 通信の暗号化（TLS 1.2以上）
- 多要素認証によるアクセス制御
- アクセス元IP制限（事務所拠点からのみ）
- 監査ログの取得・保管
- ISMAP登録済みサービスの優先選定

### 指定管理者との進め方

- **全事務所への一斉導入は行いません**。前向きな事務所からスモールスタートします
- 「監視」ではなく「サポート」のツールであることを丁寧に伝えます
- 事務所が独自に蓄積している非公式ノウハウを否定せず、公式化への橋渡しとします
