Claude Code

Claude Sonnet 5 — Opusを超えた初のSonnet

Terminal-Bench 2.1で80.4%（Opus 4.8の74.6%を超越）、FrontierCodeでSonnet 4.6比倍増（38.8% vs 15.1%）、プロンプトインジェクション耐性97%改善（31.5%→0.93%）。導入価格$2/$10はOpus 4.8（$5/$25）の6割以下。大多数のワークフローでOpusが「任意」になるコスト性能の転換点。ただし新トークナイザーで同一テキストのトークン数が最大35%増加するため、実コストは見かけほど安くならない可能性がある。

Checkpoints — 最もリクエストの多かった機能が実装

Sonnet 5リリースと同時に追加。作業進捗を自動保存し、任意のポイントへ即時ロールバック可能。/rewindコマンド（v2.1.191）と合わせ、Claude Codeの「後戻りできない」問題が構造的に解消された。FX取引ロジックの試行錯誤やリファクタリング時の安全ネットとして特に有効。

バックグラウンドエージェント安定性の集中修正

v2.1.199-201の3リリースで計42件の修正。特にLinux環境でのデーモン50秒周期強制終了バグ、スリープ復帰後の無言停止、サブエージェントのAPIエラーをサイレントに「成功」として親に報告する問題が解消。無人運用（Routines、CI/CD、夜間バッチ）の信頼性が実用水準に到達。AskUserQuestion自動継続デフォルト廃止により、無人環境での挙動がより予測可能に。

マルチエージェントオーケストレーション — 3方式の比較

Agent Teams（公式実験的機能、チームリード+メンバー構成）、Gas Town（Steve Yegge開発、「AI版Kubernetes」）、Multiclaude（ブラウニアンラチェット方式、CI通過時に自動マージ）の3アプローチが比較分析された。いずれも2026年中盤時点で実験的段階であり、トークン消費の爆発と初期プロンプト精度がボトルネック。5スキル同時読み込み対応（v2.1.199）はマルチスキルワークフローの基盤となる。

opusplan + Skills設計パターンの成熟

opusplanモード: Opus 4.8が計画段階を担当し、Sonnet 5が実行を処理するハイブリッド構成。品質とコストのバランスを動的に取る。Skills設計ではdescriptionフィールドの品質がスキル起動率を決定するという知見が定着し、「具体的動詞で始める・対象を明示・副作用を記載・トリガー条件を明確化・1-2文以内」の5原則が確立された。

4. ドメイン横断分析

横断 MCP: 金融取引から政府利用まで「AIのUSB」として制度化

MCPが今週、3つの全く異なる文脈で同時に実用化された。Robinhoodのアジェンティック取引（AI→MCP→ブローカーアカウント）、Trader MCP ServerによるMT5直接操作、Slack Claude TagのエンタープライズAI統合。プロトコルとしてのMCPが金融・エンタープライズ・開発の全レイヤーで「AIが外部システムに接続する標準インターフェース」になりつつある。7月28日のステートレス化RCが迫る中、この広範な採用はBreaking Changesの影響範囲をさらに拡大させている。

横断 Sonnet 5のコスト構造転換 × FX自動売買の採算計算

Sonnet 5の$2/$10導入価格はOpus比60%オフだが、新トークナイザーによる35%トークン増を加味すると実効コストは$2.70/$13.50相当。FX自動売買でLLMを呼び出すたびにこのコスト差が積み上がる。一方、opusplanモード（計画Opus+実行Sonnet）は取引戦略の品質維持とコスト最適化を両立する構成として有望。Routinesによる定期バックテストをSonnet 5で回し、判断が困難な場面のみOpusにエスカレーションする2段構成が、8月31日までの導入価格期間中に検証すべきアーキテクチャ。

横断 エージェントAI規制の三極同期化とリテール取引への含意

NIST Agent Standards（米）、Singapore Agent ID Card、EU AI Act Article 50、経産省ガイドラインv1.2が同一週に報道された。共通項: エージェントAIの透明性・HITL・監査証跡の制度化。Robinhoodのアジェンティック取引は、これらの規制枠組みが金融AIエージェントにどう適用されるかの最初のテストケースになる。FX自動売買でLLMエージェントを使う場合も「なぜこの取引判断をしたか」の説明可能性と介入ポイントの設計が、技術要件から規制要件に格上げされた。

横断 メタトレンド: 「エージェントの民主化」と「リスクの民主化」の同時進行

今週のデータが示す最大のメタトレンドは、かつて機関投資家・大企業だけが持てたAIエージェントツールが個人に開放される一方、それに伴うリスクも個人に転嫁されていることだ。Robinhood CEOの「機関投資家のツールを個人に」は裏返せば「機関レベルのリスクを個人に」でもある。Claude Code Sonnet 5が開発者全員にOpus級エージェント性能を、Trader MCP ServerがFX個人トレーダーにLLM自動売買を提供する。しかし規制（HITL義務・透明性開示・監査証跡）は未追従であり、5ヶ国情報機関のサイバー警告が示す通り「ツールの高度化→攻撃面の拡大」のリスクは加速中。個人が自律エージェントを運用する場合の安全設計（権限スコープ最小化、フォールバック、監査ログ）は技術的に可能だが、実装の責任は個人に委ねられている。

5. アクション提案

  • 最優先 Sonnet 5への移行とコスト影響を検証する
