4. ドメイン横断分析

エージェントがUIを置き換える：Claude Code → Claudeforce → Cowork

Claude Codeがターミナルから開発プラットフォームへ進化する動きと、ClaudeforceがSalesforceのダッシュボードUIを自然言語エージェントで代替する動き、Coworkがブラウザ操作をサイドパネルに内蔵する動きは、すべて同じベクトル上にある。「人間がUIを操作する」から「エージェントが直接アクションを実行し、人間は結果を確認する」への不可逆的シフト。MHSによる物理デバイス操作はその延長線上にある。

MCPの成熟がClaude Code/取引/エンタープライズを接続する

MCP 2026-07-28のステートレス化は、Claude CodeのMCPサーバー接続を安定化させると同時に、MT5のネイティブAIアシスタント（MCP対応）との親和性を高め、Claudeforceのようなエンタープライズ統合の基盤にもなる。来るDPoP認証への移行はAPIキー管理の負荷を下げるが、FX取引のMCP統合ではセキュリティ設計の更新が必要。3つのドメインがMCPという共通基盤で接続されつつある。

オープンウェイトの台頭がコストティアリング戦略を現実にする

Kimi K3（$3/$15）・Qwen3.8-Max（$2/$6）・LFM2.5（スマホ上30 tok/s）の登場により、「安価/軽量モデルで分類・ドラフト、フロンティアモデルで戦略判断」というコストティアリングが実現可能に。FX自動取引では、ニュース分類やインジケーター読み取りを軽量モデルで処理し、エントリー/エグジット判断のみOpus 5やSonnet 5を使う設計が合理的。Claude Codeでも、ルーチンタスクをSonnet 5、複雑な推論をOpus 5のxhighエフォートで使い分ける運用が定着しつつある。

「エージェンティック」時代のセキュリティ：攻撃面の拡大

Cursorの悪用事例、Claude CodeのAuto Modeパーミッション設計（soft_deny/hard_deny）、Browser Useのドメインallow/blockリスト、MCP DPoP認証、Singapore IMDAのエージェントデジタルID — 今週の記事群はエージェントのセキュリティという共通テーマで横串を刺せる。自律度が上がるほど攻撃面は広がり、「止められること」が「動くこと」より重要になる。取引のキルスイッチとコーディングエージェントのパーミッション設計は、抽象レベルでは同じ問題。

5. アクション提案

  1. 優先度: 高 MT5ネイティブAIアシスタントの評価と、FX自動取引アーキテクチャの再検討 MT5組み込みAIがMCP対応・無料・低レイテンシで登場し、3週間で1兆トークンの実績を出した（#3754, #3755）。現行の外部LLM連携設計と比較して、レイテンシ・コスト・セキュリティのトレードオフを実機で検証する価値がある。まずMT5のAIアシスタント機能をデモ環境で触り、現行EAとの統合可能性を見る。今やるべき理由: 機能が急速に進化中で、アーキテクチャ判断を後回しにすると手戻りが大きくなる。
  2. 優先度: 高 Claude Code のConcise出力 + /design を日常ワークフローに組み込む Week 34-35で正式導入されたConcise出力は、トークン消費とノイズの同時削減に直結する（#3765）。/designはプロトタイプ作業でのタブ切り替えを不要にする（#3766）。settings.jsonに「output_style: concise」を設定し、次のUI作業で/designを試用するだけで効果を確認できる。今やるべき理由: 既にGAまたはリサーチプレビューとして利用可能であり、設定変更のみで即効性がある。
  3. 優先度: 中 CLAUDE.mdの200行以内ダイエット Chromaのベンチマークがコンテキスト長増加による精度低下を実証した（#3777）。現在のリポジトリのCLAUDE.mdファイル群をGrepで総行数確認し、200行超のものをHTMLコメント活用やHooksへの移行で圧縮する。SmartScopeの「CLAUDE.mdはリクエスト、Hooksは保証」ガイドライン（#3749）を判断基準に使う。
  4. 優先度: 中 クロスセッション通信を活用したFX並列監視のPoC ListAgents/SendMessageによるClaude Codeインスタンス間通信が公式ドキュメント化された（#3773）。異なるターミナルで通貨ペア別・戦略別のエージェントを走らせ、テキストメッセージで協調させる構成のPoCを組む価値がある。Agent SDK（#3774）を使えばCLI外からも同様のマルチエージェント構成が可能。
  5. 優先度: 中 MCP DPoP認証への移行準備（ロードマップ追跡） 8/22のMCPロードマップでDPoP + Workload Identity FederationがAPIキー置換の方向性として明示された（#3761）。現在のMCPサーバー接続がAPIキーベースの場合、移行タイムラインを追跡し、先行して認証設計を見直しておく。Cloudflareの実装パターン（#3743）が参考になる。
