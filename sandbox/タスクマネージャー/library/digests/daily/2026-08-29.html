Claude Code・エコシステム

Week 35：ループ可視化でルーチン運用が変わる

Claude Code v2.1.247（2026-08-26リリース）がWeek 35のハイライトとして届いた。（一次ソース確認済み）

最も運用に効くのが `/usage` コマンドへの Loopsブレイクダウン追加だ。ループ実行回数・合計トークン・実行あたりトークン・最終実行時刻が一覧で確認できるようになった。日次収集のような繰り返しタスクがトークンを何件消費しているか定量的に把握でき、コスト異常の早期発見につながる。エンタープライズ向けの `modelPricing` マネージド設定も追加され、契約割引を `/cost` に正確に反映できるようになった。起動バイナリは75MBへのダウンサイズ（従来比78%削減）で、CI/CDやVPS環境での取り回しが軽くなる。

  • 参照: https://www.gradually.ai/en/changelogs/claude-code/

クロスセッションメッセージング：マルチエージェント協調が実用フェーズへ

v2.1.224（2026-08-07リリース）から搭載された `ListAgents` + `SendMessage` の公式ドキュメントが整備された。（一次ソース確認済み）

別ターミナルやworktreeで動く複数のClaudeインスタンスが互いを検出してテキストメッセージを送受信できる。セキュリティ設計が堅牢で、送信されたメッセージが相手セッションの権限を昇格させることは設計上不可能。OSユーザー分離・パーミッションクラシファイア通過が前提のため、FX自動取引のように複数エージェントが異なる戦略・市場を並列監視するアーキテクチャに直接応用できる。macOS/Linux対応、Windows・Bedrock・GCP非対応という制約は押さえておきたい。

  • 参照: https://code.claude.com/docs/en/cross-session-messaging

プラグインエコシステムの成熟と「5本に絞れ」ルール

2026年6月時点でClaude Codeプラグインは9,000本超。ただし本番実用に耐えるのは約100本という選択コスト問題が顕在化している。Composioが示すガイドラインは「5〜6本のフォーカスドスタック」だ。

実用三本柱として紹介されているのが、Superpowers（マルチサブエージェント並列実行）・Frontend Design（デザイン特化）・Composio（外部サービス統合）。中でも Context7 は「常に最新ドキュメント参照」でClaude Agent SDK/MCPの仕様変更追従に有効で、APIの変化が速い現状に刺さる。

  • 参照: https://composio.dev/content/top-claude-code-plugins

CLAUDE.md：「何を書くか」より「どう書くか」

DEV Communityの2026年版ベストプラクティスガイドは、定量データが光る。ベクターDBのChromaで適切なCLAUDE.mdなしでは精度95%→60%に低下するという具体的な数字は、「書かなくていい」という甘えを排除する。

実践指針として明確なのが Structure > Prose（箇条書き・見出しを優先）と HTML commentゼロコストトリック（`<!-- hidden instructions -->` はトークンを消費しない隠し記法）。200行ガイドラインの根拠を示しながら、ワークスタイルを明示することの重要性を強調している。定期的なCLAUDE.mdレビューの基準として手元に置いておきたい。

  • 参照: https://dev.to/nishilbhave/claudemd-best-practices-the-complete-2026-guide-435j
