## Claude Code・エコシステム

### CLAUDE.mdの「書くべき内容」が収束してきた

日本語コミュニティでCLAUDE.md実践ガイドが2本同時に登場した。
Qiitaのガイド（[リンク](https://qiita.com/pythonista0328/items/7864c2728c5af628c0a0)）が示す核心は「Claudeがコードから推測できないルールだけを書く」という選別基準だ。特筆すべきは禁止事項の書き方——「〜を直接呼び出すことは禁止」という命令・禁止形式にするとClaudeの遵守率が実証的に向上するという知見で、5種のコピペ用テンプレート（個人・チーム・API連携・フロントエンド・バックエンド）も公開している。

ソウゾウメディアのガイド（[リンク](https://media.souzoh-official.com/claude-md/)）はより構造的で、CLAUDE.mdの4点の背骨「①プロジェクト目的・②絶対守るルール・③環境情報の在り処・④品質基準と完了条件」を提示し、規模別の構成例（単一ファイル→ディレクトリ別分割→hooks連携）を示している。チームでCLAUDE.mdを共有したことで「変なライブラリ提案」苦情がゼロになった事例や、コードレビュー指摘が半減した事例も掲載。2026年最新機能（Skills・routines連携）にも対応済みだ。

両ガイドに共通する原則「200行を目安にファイル分割する」は、このリポジトリで既に実践している構成と一致している。

### Claude Agent SDKとMCPエコシステムの成熟

alloq.digitalによるClaude Agent SDK完全ガイド（[リンク](https://alloq.digital/en/blog/claude-agent-sdk/)）は、2026年の主要アップデートとして「サブエージェントの深さ3までのネスト（旧1から拡張）」「REPLのセッション永続化（code_execution_20260120）」「Workload Identity Federation（WIF）認証」を挙げている。よくある失敗——settings.jsonの構文エラー、コマンドパス解決失敗、サーバー起動失敗——への対処法が具体的で実践的だ。

MCPサーバーのTop 10ガイド（[リンク](https://www.totalum.app/blog/claude-code-mcp-servers-2026)）は2026-07-28新仕様への対応状況別にサーバーを評価しており、インストール前のベンダー信頼性確認という原則を強調している。

### MCP 2026-07-28仕様が確定（一次ソース確認済み）

MCPローンチ以来最大の仕様改訂が7月28日に最終確定した（[公式発表](https://blog.modelcontextprotocol.io/posts/2026-07-28/)）。
核心はステートレスプロトコルへの転換だ。initializeハンドシェイク廃止・Mcp-Session-Id廃止・requestごとにcapabilitiesを送信する方式に変わり、スティッキーセッションなしのラウンドロビンLBで動作可能になった。これにより標準HTTPインフラやサーバーレス/エッジ環境への展開が現実的になる。

MCPServers.orgの技術解説（[リンク](https://blog.mcpservers.org/posts/mcp-spec-2026-07-28)）によれば、既存のステートフルサーバーからの移行は「セッション管理削除→ステートレスハンドラー書き換え→LBテスト」の3ステップチェックリストで対応できる。新拡張フレームワーク（MCP Apps: UI埋め込み、Tasks: 長時間非同期処理委譲）も正式化された。次期v2026-11-05ではRoots・Sampling・Loggingが削除予定のため、現在これらを使っている場合は移行計画が必要だ。

MintMCPのエンタープライズガイド（[リンク](https://www.mintmcp.com/blog/enterprise-development-guide-ai-agents)）は200以上のエージェントを運用する規模での可観測性（エージェントごとのコスト帰属・レイテンシ追跡）とMCPトンネルの権限管理を詳述。MCPトンネルのAPIが`/v1/organizations/tunnels`から`/v1/tunnels`（Claude API）に移動した点（`anthropic-beta: mcp-tunnels-2026-06-22`ヘッダー必要）は要確認だ。

## AIニュース・業界動向

### LLM 0.32リリース——CLIからリーズニングが見えるようになった（一次ソース確認済み）

Simon WillisonがLLM 0.32を2026年8月4日にリリースした（[リンク](https://simonwillison.net/2026/Aug/4/new-release-of-llm/)）。初期リリース以来最重要とする今回の更新で、CLIでClaude Sonnet/OpusやGPT-4o系モデルの内部思考プロセスを直接見られる「リーズニングトレース表示」が加わった。Claude系モデルにはWebSearch・WebFetch・CodeExecution・AnthropicMCPがサーバーサイドツールとして提供され、クライアント側の複雑性が大幅に削減された。デフォルトモデルはGPT-5.6 Luna（$0.20/$1.20/Mトークン）に変更。`pip install -U llm`でアップグレードできる。

あわせてTECH NOISYの8月4日分まとめ（[リンク](https://tech-noisy.com/2026/08/05/ai-daily-news-2026-08-04/)）が伝える動向：Claude Opus 5（7月24日リリース）はOpus 4.8比でディープリーズニングと長期エージェント作業で大幅向上しつつ価格$5/$25/Mのままで、Fable 5の約半額という価格競争力が注目されている。Anthropicは旧Slackアプリを完全廃止しClaude Tag（claude.ai/tag）に全面移行（8月4日完了）。OpenAIはアクティブユーザー10億人超・導入企業200万社超を公表した。

### AI規制の「三波」が完成——公務員として押さえておく構造

2026年夏、世界のAI規制が3つの異なるアプローチで同時に形成された。

EU AI Act（8月2日施行）は高リスクAIシステム（医療・採用・信用評価等）にリスク管理・ログ&トレーサビリティ・人間監視を義務化。汎用AIプロバイダーは透明性要件・著作権遵守・能力評価が必要で、ログ保存期間は最低3年だ。中国（7月15日施行）はAIエージェントの権限をティア1-3に分類し、意思決定の影響度・可逆性・金額規模に応じた事前届出を世界初の国家フレームワークとして制度化した。

米国は対照的に自主規制路線を選択した（一次ソース確認済み）。Anthropic・OpenAI・Google・Meta等約12社とホワイトハウスが8月4日に合意したのは、フロンティアモデルのリリース前30日間、連邦政府への早期アクセスを提供する自主的枠組みで、強制力はない（[出典](https://ny1.com/nyc/all-boroughs/politics/2026/08/04/source--voluntary-federal-regulatory-framework-for-advanced-ai-models-finalized)）。「Great American AI Act」が州法との連邦優越条項をめぐる対立で停滞していることへの業界側の先回り対応だ。

EveAICore（[リンク](https://eveaicore.com/blog/ai-regulation-2026-what-changed)）およびDualMedia（[リンク](https://www.dualmedia.com/ai-governance-framework-2026/)）の分析が提示するAIチームへの即時アクションは共通している：①AIシステムインベントリ管理（用途・リスク分類・所有者の記録）、②リスクスコアリング（影響度×可逆性×自律度）、③改ざん防止ログ3年以上保存、④AI特有のインシデント対応フロー整備。公務員として組織でのAI導入議論が始まった際、これらは準拠性確認の出発点になる。
