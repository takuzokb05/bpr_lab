## 今日のハイライト

Claude Code v2.1.207がBedrock・Vertex AI・Foundryでの「auto modeデフォルト化」という企業利用の転換点を迎えた。同時に、MCPの次世代仕様（2026-07-28 RC）がステートレス化・エンタープライズ認可を実装する一方、セキュリティ研究者から4種の新攻撃面が指摘された。規制面ではEU AI Actのうち汎用AI（GPAI）への執行権限が8月2日に発動し、グローバルなコンプライアンス対応が本格化する。モデル価格競争ではGrok 4.5が主要ベンチマーク上位陣と1pt以内の性能差でコストは5分の1以下という構図が鮮明になった。

## Claude Code・エコシステム

### v2.1.207：企業向けの地殻変動（一次ソース確認済み）

7月11日リリースのClaude Code v2.1.207は、クラウド基盤経由の利用者にとって静かな破壊的変更だった。Bedrock・Vertex AI・Azure Foundryで`auto mode`がデフォルト有効化され、これまで必要だった`CLAUDE_CODE_ENABLE_AUTO_MODE`環境変数の設定が不要になった。デフォルトモデルはClaude Opus 4.8に変更。

DigitalAppliedの詳細分析が指摘した重大な盲点がある――Anthropic管理コンソールの`disableAutoMode`設定がBedrock/Vertex/Foundry環境には**届かない**。コンプライアンス基盤を理由にクラウド基盤を選んだ組織が、中央ポリシー制御が及ばない状態に置かれるという逆説だ。無効化にはself-hostedゲートウェイかMDM/Windowsレジストリが必要になる。設定の落とし穴として`autoMode.environment`で`"$defaults"`を省略するとAnthropicのデフォルト保護が全消去されることも注意が必要だ。

セキュリティ修正として、非対話実行でコンセントダイアログをバイパスできた重大バグとプラグインフックでのシェルインジェクション問題も同時修正されている。
（参照: [DevelopersIO](https://dev.classmethod.jp/en/articles/20260711-cc-updates-v2-1-207/)・[DigitalApplied](https://www.digitalapplied.com/blog/claude-code-auto-mode-bedrock-vertex-foundry-2026)）

### 7月11日週の機能アップデート群

個人Pro/Maxユーザー向けの変化として、**Artifacts機能がPro/Maxプランに解放**された（v2.1.202、従来Team/Enterprise限定）。`/review`コマンドは高速確認専用に戻り、詳細なマルチエージェントレビューは`/code-review <level> <pr#>`に分離された。`/doctor`がCLAUDE.mdの簡素化を自動提案する新チェックを追加、`/cd`にディレクトリパス候補表示も追加されている。**週次利用制限50%増プロモーションは7月19日PT 23:59まで延長**中で手続き不要・自動適用。
（参照: [Qiita](https://qiita.com/saitoko/items/992631068d62dfef46b0)・[HelpNetSecurity](https://www.helpnetsecurity.com/2026/07/13/claude-code-weekly-limits-promotion-extended/)）

7月1〜8日の振り返りとして、**Fable 5が輸出規制停止から復帰**しPro/Max/Teamで追加料金なし提供が再開、**Claude Cowork**（デバイス間クラウド同期）がMaxプランでベータ開始、**Microsoft 365コネクタに書き込みツール追加**でメール・カレンダー・OneDrive操作が可能になった。
（参照: [yougears-lab](https://yougears-lab.com/claude-update-20260708/)）

### MCP 2026-07-28 RC：進化とリスクの同時到来

次世代MCP仕様（2026-07-28 RC）の中心的変更は**ステートレスコア化**だ。従来のinitialize/initializedハンドシェイクが廃止され、クライアント情報が全リクエストの`_meta`フィールドに埋め込まれる自己記述型になる。これによりラウンドロビンLBがセッションアフィニティなしで動作可能になり、企業向けスケーラビリティが向上する。**ID-JAG**（RFC 8693 Token Exchangeベースのエンタープライズ認可）でSSO連携・インタラクティブ同意不要な認証フローも実現する。

しかしSecurityWeekが4種の攻撃面を実証的に報告した。予測可能なトラッキングIDによるワークフローハイジャック、新設HTTPヘッダー経由のAPIキー漏洩、MCP Appsプロトコル拡張が導入するXSS、そしてTasks extensionを介したDoS（単一リクエストから高コスト処理を起動し即時切断可能）だ。旧バージョンは2026年7月28日で廃止指定（12ヶ月移行期間）。SDK BetaはPython `mcp[cli]==2.0.0b1`・TypeScript `@modelcontextprotocol/server@beta`で提供中。
（参照: [Fmind](https://fmind.medium.com/mcp-2026-07-28-stateless-core-enterprise-authorization-and-sdk-betas-2646a980d594)・[SecurityWeek](https://www.securityweek.com/new-enterprise-ready-mcp-specification-brings-new-security-challenges/)）

## AIニュース・業界動向

### フロンティアモデルの価格競争：Grok 4.5の衝撃（概ね確認済み）

2026年7月時点のモデル価格対性能比較で構図が明確になった。価格（入力/出力 per Mtok）はGrok 4.5が$2/$6なのに対し、Fable 5は$10/$50、GPT-5.5/5.6は$5/$30。Terminal Bench 2.1では3モデルが83〜84%台に収束（1pt差以内）で性能差はほぼなくなっている。

ただしコーディングの複雑タスク（DeepSWE 1.1）ではFable 5 70%・GPT 67%・Grok 53%と17pt差があり、得意不得意は残る。加えてGrokはEU未提供（7月中旬目標）でハルシネーション率が高い（54%との報告）という制約もある。汎用タスクや大量生成用途ではGrok 4.5のコスト優位性が品質差を上回る可能性が高まっている。
（参照: [The Decoder](https://the-decoder.com/grok-4-5-is-so-cheap-compared-to-fable-5-and-gpt-5-5-that-benchmark-gaps-may-not-matter-much/)）

### EU AI Act：8月2日に執行権限が発動（一次ソース確認済み）

2026年8月2日、EU AI ActのGPAI（汎用AIモデル）に対する欧州委員会の監督・執行権限が発動する。これは「新たな義務の開始」ではなく「2025年8月から課されていた義務への執行権限が有効化」されるタイミング。罰則上限は最大€1,500万または全世界年間売上3%。チャットボット・感情検出・合成コンテンツへのAI使用開示（第50条・透明性義務）も完全施行となる。高リスクAI（Annex III）はDigital Omnibusにより2027年12月まで猶予が続く見込み（正式採択待ち）。
（参照: [InformedClearly](https://informedclearly.com/en/ai/55795/eu-ai-act-compliance-deadline-2026)）

### 中国AI規制：ローカルモデルへの影響

中国当局が海外からの先進AIモデルアクセス規制強化を発表。Qwen・DeepSeek・Baichuan・Yiシリーズが対象で、HuggingFace・ModelScope経由のダウンロード制限またはIPブロックの可能性がある。DeepSeek APIのデッドラインは7月24日とされており、代替モデルリサーチと事前のGGUF形式ローカルバックアップが実務的な対策として挙げられている。
（参照: [warokai](https://warokai.com/2026/07/08/china-ai-regulation-2026-local-llm-guide/)）

## AIトレーディング

LLMによる自動取引の実態について、2本の記事が異なる角度から論じた。実績面では「第1週で$1,000から15%損失」「数ヶ月で大幅利益」と報告が混在し、一貫した人間超越の証拠はまだない。Robinhoodが2026年5月に直接エージェント接続機能を発表したことは象徴的だが、実用的結論は「LLMは情報収集・フィルタリング・アラート生成に有効、執行はルールベース自動化」というハイブリッド構成が現実解とされている。

Bitsgapが強調したのはセキュリティリスクで、2025年に暗号スキャムで$170億損失・AI活用詐欺は従来比4.5倍収益という数字が背景にある。AIエージェントへのウォレット権限付与が攻撃面を拡大させる問題は、FX自動取引への応用を検討する際も参考になる。推奨ワークフローは「AIリサーチ→ルールベース戦略定義→バックテスト→デモ→スモールポジション展開」の5段階。
（参照: [CoinEdition](https://coinedition.com/llm-trading-in-2026-can-ai-agents-actually-outperform-humans/)・[Bitsgap](https://bitsgap.com/blog/ai-trading-agents-vs-trading-bots-in-2026-why-smarter-isnt-safer)）
