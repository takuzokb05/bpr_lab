## Claude Code・エコシステム

### Claude Opus 5 ―― effort toggle が実装者の武器になる

7月24日にリリースされた Claude Opus 5 は「effort toggle」（low/medium/high の3段階）を最大の差別化点として打ち出している（**一次ソース確認済み**）。
価格は Opus 4.8 と同一（$5/$25/M tokens）でありながら、OSWorld 2.0 で Fable 5 を超え、SWE-bench Verified 96% を達成している。
ポイントは「モデルを変えずにコストを変えられる」点だ。長時間エージェントタスクなら high、ルーティン要約なら low ―― この制御をコード側で持てることで、Claude Code ヘビーユーザーにとっては API コストの最適化が格段にやりやすくなる。
1M トークンコンテキスト・128K 出力対応で、長期プロジェクトの継続セッション設計にも余裕が生まれた。

- 一次情報: [Fortune](https://fortune.com/2026/07/24/anthropic-debuts-claude-opus-5-with-feature-that-lets-users-toggle-between-cost-and-capability/)

### GitHub Copilot に Opus 5 が追加 ―― マルチモデル IDE の完成形へ

Anthropic のリリース当日（7月24日）に GitHub Copilot のモデル選択肢に Opus 5 が追加された。
Copilot はすでにマルチモデル対応 IDE として設計されており、今回の追加で「複雑な長時間コーディングを IDE から直接 Opus 5 に委任する」フローが整った。
Anthropic と GitHub/Microsoft のエコシステム連携の深化を示す公式記録として見ておきたい。

- 公式 Changelog: [GitHub Blog](https://github.blog/changelog/2026-07-24-claude-opus-5-is-now-available-in-github-copilot/)

## AIニュース・業界動向

### EU、AI ギガファクトリー7拠点の公募を本日開始（**一次ソース確認済み**）

本日2026年7月30日、EU が AI ギガファクトリー計画の公募を正式開始した。公的資金 €100億（約 $114億）で7拠点建設、民間投資込みの総額目標は €300億。
各拠点には最先端チップ最低10万枚（現行 EU データセンターの約4倍規模）を配備し、フロンティア AI モデルのトレーニング・推論・ファインチューニング向けインフラを整える。
入札締切は2026年11月12日、落札は2027年中頃の予定。8月2日の EU AI Act 完全施行と重なるタイミングで、欧州が「規制＋インフラ」の二本柱で AI 主権戦略を進める姿勢が鮮明だ。

- 一次情報: [Bloomberg](https://www.bloomberg.com/news/articles/2026-07-30/eu-pledges-10-billion-in-public-funding-for-new-ai-data-centers)

### 米国・AI AGENT Act ―― 金融代理エージェントへの受託者責任（**一次ソース確認済み**）

Warner 上院議員が6月29日に公開した AI AGENT Act 討議草案が、法律・セキュリティ両面から注目を集めている（草案段階・法案正式提出前）。
三本柱は：①大規模プラットフォーム（月間利用者5000万超）への AI エージェントの非差別アクセス権、②FTC による信頼 AI エージェント認定レジストリ、③「Custodial User Agent（CUA）」への登録義務と受託者責任。
CUA は「金融管理・契約締結・購買代行を行う AI」と定義されており、FX 自動取引エージェントは定義上この範疇に入る可能性が高い。
Davis Wright Tremaine の法的分析は「消費者保護の衣をまとった競争規制」と評しており、FTC の既存権限との重複や州法との整合性に課題が残る。中国が7月15日に施行した AI エージェント規制（三層決定承認制）との制度的対比も参考になる。

- 法的分析: [Davis Wright Tremaine](https://www.dwt.com/blogs/artificial-intelligence-law-advisor/2026/07/ai-agent-act-consumer-ai-regulation)  
- セキュリティ視点: [CyberScoop](https://cyberscoop.com/ai-agent-act-senate-draft-bill-mark-warner/)

### 長時間エージェントの安全設計 ―― 「継続実行プラットフォーム」フェーズへの移行

Eguweb の7月21〜27日にかけての連続解説記事が、エージェント AI の実装論として有用な視点を提供している。
AI は「生成ツール」から「業務プロセス内の継続稼働エンジン」へと移行しつつあり、管理すべき4要素として「①アクセスできるデータ ②実行できるオペレーション ③発生するコスト ④生成出力と説明責任」が整理されている。
EU AI Act 施行直前週のまとめでは、長時間エージェントの実装標準として「オプト・イン型ヒューマン承認フロー」「コスト上限設定」「停止・再開チェックポイント設計」が定着しつつあることが報告されている。
FX 自動取引システムの長時間稼働設計でも、これらのチェックポイント設計とコスト上限設定の標準実装が推奨水準になりつつあるといえる。
