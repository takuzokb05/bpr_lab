## Claude Code・エコシステム

### Skillsの設計論が出揃った

この日、Claude Code Skillsに関する実践ガイドが4本同時に登場し、設計パターンの輪郭が鮮明になった。

ビジョナリージャパンの[完全ガイド（一次ソース確認済み）](https://visionary-jp.co.jp/claude-code-guide/)はインストールからOPUS 4.8対応・3段階エージェント・コミュニティマーケットプレイスまで日本語で網羅しており、チーム展開時のランディングページとして最適だ。

スキル作成のアプローチとしては、Orca社が「手動作成 / Claudeに生成させる / スキルから派生させる」という3パターンを整理した。一方Uravationは「プロジェクト単位・ユーザー単位・組織単位の3層スタック設計」という配置モデルを提案しており、大規模展開時の構造化指針として役立つ。コードレビュー・テスト生成・デプロイ・i18n翻訳など7種のSKILL.mdサンプルも掲載されている。

最も実践的だったのがAumiqxの「30スキル + MCPサーバー群 + 自己学習フック」構成記事だ。特筆すべきは**PostToolUseフックでCLAUDE.mdを自動更新する「自己学習フック」**の実装例で、チーム向けオンボーディング設計と合わせてプロダクション投入事例として参考になる。

### MCPはステートレス時代へ——移行ガイドが出揃う

MCP 2026-07-28仕様の移行ガイドが英日ほぼ同時に公開された。変更の核心は「ステートレスプロトコルコア」への転換で、従来のセッション維持型サーバーからの書き直しが必要になる。その代わりCloudflare WorkersやVercelなどの標準インフラで動作可能になり、運用コストが大幅に下がる。

CData（エンタープライズ連携ベンダー）の[日本語ガイド](https://jp.cdata.com/blog/mcp-server-best-practices-2026)はOAuth 2.1認証実装・エラーハンドリング・レート制限・ログ設計まで本番品質の設計パターンを体系化しており、エンタープライズ環境での実装リファレンスとして使える。

- 参照: https://aaif.io/blog/mcp-2026-07-28-whats-changing-and-how-to-migrate

## AIトレーディング

### 実績レポートと技術アーキテクチャ——楽観と現実が交差

AIトレーディングに関して、パフォーマンス面と技術面の両軸からレポートが出た。

DEV Communityの[実績比較記事（一次ソース確認済み）](https://dev.to/lightningdev123/best-ai-trading-agents-in-2026-can-they-really-deliver-consistent-returns-2fgl)は、TradingAgents（GitHub 80,000 stars）・ai-hedge-fund・FinRLなど主要OSSの30日実績をレビューした。S&P500比+7%超過リターンのケースがある一方、1週間で15%超の損失を出したケースも報告されており、**自己報告数値のため個別ケースは要注意**だ（FINQ AI ETFsがS&P500を上回る+15〜+27%達成は第三者確認済み）。また**RobinhoodがMCP経由でAIエージェントとの直接ブローカー連携「agentic finance」を2026年5月に発表した**ことも言及されており、これは複数メディア一次ソース確認済み。

技術面ではTokalpha Labsがアーキテクチャを整理した。LLMトレードの強みは「決算トランスクリプト・ニュース・SNS・価格データを統合処理した文脈的推論」にあり、従来アルゴが苦手とするマクロシフト局面での優位性が大きい。一方でレイテンシ問題（LLMの応答速度はHFTと相性が悪い）は依然として課題で、複数LLM（Claude Opus 4.8・GPT-5・Gemini等）の特性比較と適材適所の選択指針を提供している。自動取引システムのリスク管理層設計の参考になる。

- 参照: https://tokalpha.ai/blog/llms-in-algorithmic-trading
