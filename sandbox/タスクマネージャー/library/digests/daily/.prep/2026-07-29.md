## Claude Code・エコシステム

### ベストプラクティスの収束：「探索→計画→コーディング」が標準ワークフローに

OpenHandsが7月に公開した10のベストプラクティス（一次ソース確認済み）は、Claude Codeをチームで使う上での設計原則を整理している。核心は「CLAUDE.mdは200行以内」という制約だ。記事では「95%→60%の精度低下」という数値が引用されているが、**これは要注意**：実際にはChroma 2025ベンチマークで示された長文コンテキスト全般の「lost in the middle」効果からの数字であり、CLAUDE.md超過に特化した実測値ではない。ただし200行制限自体は複数ベストプラクティスで一致しており、実用上は有効な指針として扱える。

ツール選択の設計原則として「Hooks=強制ルール、Skills=文脈知識、Subagents=委任境界」を明確化している点は、大規模エージェント設計をしている身には直接使えるフレームワーク。また、gitワークツリーを使った並列エージェント実行と、チームMakefileで「1コマンド実行」環境を揃える推奨も実践的。
[OpenHands: Claude Code Best Practices for Agentic Coding 2026](https://www.openhands.dev/blog/claude-code-best-practices-agentic-coding)

genai-ai.co.jpの7月版解説（25機能・30ポイント完全ガイド）は、v2.1.101対応でxhigh effort・エージェントチーム・Cowork連携まで網羅する日本語記事として参照価値が高い。業務時間30%削減という定量データも記載されており、組織内への説明材料として使いやすい構成になっている。入門から実運用まで1本で把握できる点も○。
[25機能解説](https://genai-ai.co.jp/ai-kanri/blog/cc-code-features-25/) / [完全ガイド30+](https://genai-ai.co.jp/ai-kanri/blog/cc-yt-claude-code-complete-guide-30/)

## AIニュース・業界動向

### NVIDIA OSAIA：AIエージェントセキュリティのOSS連合が始動

NVIDIA主導で37組織が「Open Secure AI Alliance（OSAIA）」を設立した（一次ソース確認済み）。直接のきっかけは7月のHugging Faceセキュリティインシデントで、クローズドAIによる対応が不十分だったことを教訓にオープンなセキュリティエコシステムの必要性が認識された結果だ。

NVIDIAの初期貢献はNOOAフレームワーク（Apache 2.0）。エージェント行動のテスト・トレース・監査機能をOSSで提供する。HPEがゼロトラスト認証、Hugging FaceがSafetensors、IBM/Red HatがLightwell、MicrosoftがMDASHを技術提供。注目点はOpenAI・Anthropic・Googleがいずれもメンバー不参加な点で、Big Threeを除くプレイヤーによるOSSセキュリティ連合という構図になっている。
[NVIDIA Official](https://blogs.nvidia.com/blog/open-secure-ai-alliance/) / [The Hacker News](https://thehackernews.com/2026/07/nvidia-forms-37-member-open-secure-ai.html)

### Kimi K3：オープンウェイト収束の加速

Moonshot AIがKimi K3（2.8Tパラメータ、MoE構成）を7月26日夜にオープンウェイトで公開した（一次ソース確認済み）。MoEの実効パラメータは記事によって「50B」「104B active per token」と記述が異なるが、これはMoE構成の計算方法の差異によるもの。1Mコンテキスト・Day-0ホスティング（Together AI/Modal）対応で、実質的にフロンティア級の性能が無償で使える状態になった。

Forbesの分析が指摘する通り、クローズドとオープンウェイトの性能差は急速に縮まっており、プロプライエタリモデルの差別化軸が純粋な性能以外（サポート・エコシステム・コンプライアンス）に移行しつつある。中国インフラ経由のデータフローを懸念する場合はセルフホスティングが有効な回避策として評価されている。
[Forbes分析](https://www.forbes.com/sites/geruiwang/2026/07/27/why-kimi-k3-signals-a-convergence-toward-open-weight-models/) / [ExplainAI技術詳細](https://explainx.ai/blog/kimi-k3-open-weights-2-8-trillion-parameters-july-2026)
