## Claude Code・エコシステム

### v2.1.263到達と開発者体験の深化

Claude Codeは2026年9月現在でv2.1.263に到達し、週1〜2本のペースでアップデートが続いている。直近の主な変更は3点。`bashOutputMaxChars` / `taskOutputMaxChars` 設定で出力上限が最大128Kに拡張され、長時間タスクのログ取りこぼしが減った。v2.1.260からはサイドバーに未コミット変更のdiff表示パネルが追加され、変更管理がIDEに近い体験になった。そして `maxEffortLevel` コントロールにより、モデルの推論深度をタスク性質に応じて制御できるようになっている。[Claude Code Changelog](https://www.gradually.ai/en/changelogs/claude-code/)

モデル面では、Claude Fable 5.1がデフォルトモデルに昇格（Pro/Team StandardはSonnet 5）。Fable 5.1のcache reads料金は$0.25/MTok、Terminal-Bench-Scienceスコアは52.6%と前世代Fable 5の24.7%から倍増しており、Claude Code作業での推論品質が体感できるレベルで向上している（一次ソース確認済み）。AdminAPI のGA化も進み、`anthropic-workspace-id` レスポンスヘッダー追加・Managed Agentsの予算制御・地域固定推論・GitHub経由スキルロードも加わった。[Claude Code アップデート完全ガイド](https://uravation.com/media/claude-code-update-operation-guide-2026/)

### Function Hooks：「いつ」から「どの関数で」へ

フラグ付きプレビューとして登場した **Function Hooks** は、既存のLifecycle Hooks（セッション開始/終了・ツール呼び出し前後）とは一線を画す。Lifecycle Hooksが「いつ介入するか」を制御するのに対し、Function Hooksは「どの関数・ツールが呼ばれたとき」という粒度で直接フックできる。特定MCPツール実行前のバリデーション、外部APIコールのログ記録、ファイル操作前の確認ダイアログなど、ガードレール構築の幅が広がる。同タイミングでシンボリックリンク経由のファイルアクセスバグ（スキル/エージェント/フック内でシンリンクパスがスキル外のファイルを読めていた）の修正も実施済み。`~/.claude/settings.json` の `experimental` フラグで有効化可能。[Function Hooks Preview](https://claudefa.st/blog/tools/hooks/function-hooks)

### 4ヶ月の実践知見：HooksとCLAUDE.md

4ヶ月間のClaude Code日常利用を経た実践者のセットアップ公開が参考になる。「最も効いたのはHooksによる自動lint」という証言と、`PreToolUse` で危険コマンドを遮断・`PostToolUse` でファイル変更後に自動lint実行するパターンは即採用できる構成だ。CLAUDE.md は150行以内でアーキテクチャ・禁止事項・頻出コマンドを収め、コンテキスト管理の核として機能。スキルは「5本以上になると管理コストが上がる」という実体験も記録されており、スキル数を絞る判断に使える。subagentsとgit worktreeの組み合わせによる並列開発も実績あり。[My Claude Code Setup After 4 Months](https://okhlopkov.com/claude-code-setup-mcp-hooks-skills-2026/)

Claude Agent SDKについては、Claude Code内部と同じエージェントループをPython/TypeScriptライブラリとして使える構造が整理されている。プロダクション固有の失敗パターン（トークン予算オーバー・レート制限・ツール冪等性問題・コンテキスト断片化）への対策として、指数バックオフ付きリトライ・チェックポイント機構・デッドレターキューが推奨されている。Managed Agentsとの使い分けは「自前サーバーが要る→SDK、サーバーレス・マネージドが良い→Managed Agents」が基本指針。[Claude Agent SDK Production Patterns](https://www.digitalapplied.com/blog/claude-agent-sdk-production-patterns-guide)

### 9月のモデルリリース競争：Fable 5.1・GPT-6 Astra・GLM-5.3

2026年9月11日時点で11モデル・7プロバイダーがリリースされた。主要3本を整理する。

**Fable 5.1**（9月1日GA）はFable 5同価格でcache reads $0.25/MTok。Terminal-Bench-Scienceスコア52.6は前世代Fable 5の24.7から倍増で、Claude Codeでの作業推論品質の向上が数字に表れた（一次ソース確認済み）。**GPT-6 Astra**（9月3日）は$10 input / $50 output（cached $1）/ 1Mコンテキスト・128K出力。**GLM-5.3-Flash**（Alibaba/Z.ai）は320B/18B・1Mコンテキスト・MIT weights・DeepSWEスコア63.4（GLM-5.2: 46.2から大幅向上）とオープンウェイトで注目を集める。なお、Claude Sonnet 5の標準価格（$2/$10 per MTok）は9月1日予定の値上げが撤回されたことも記録された。[September 2026 AI Model Updates](https://local-ai-zone.github.io/blog/September_2026_AI_Model_Updates.html)

### EU AI Act：9月から「執行」フェーズへ

2026年8月2日、EU AI Actの高リスクシステム移行期間が終了し、9月からEU AI Officeとコンプライアンス検査機関による初回検査が始まった（一次ソース確認済み）。違反時は最大€3,500万または全世界売上の7%の制裁金。日本の公務員・行政機関にとっても、EU由来サービス・調達するAIシステムの技術文書整備・内部監査・第三者評価が今後の必須要件になる流れだ。

米国側はパッチワーク状態で、コネチカット州のCT SB 5（規制サンドボックス・チャットボット規制・独立検証機関を含む包括AI法）可決、カリフォルニアのFrontier AI Safety Act（SB 1047）署名判断（期限9月30日）、ブラジルのBill 2338/2023上院採決（9月16日予定）など、地域ごとの動きが並走している。規制の重心が準備段階から執行段階へ移行しており、各国の対応が本格化する。[AI Regulation September 2026 Global Update](https://cubbbix.com/blog/ai-regulation-september-2026-global-update)

## AIトレーディング

### LLMトレーディング：「研究から実インフラ」への転換点

2026年5月にRobinhoodがAIエージェントの証券口座直接接続を発表し、CEOが「agentic financeの始まり」と表現した。LLMトレードは「実験的アイデア」から金融インフラへの統合段階に入った。ベンチマークでは Opus 4.1がアルゴリズム取引で最高性能、Claude Sonnet 4.6はPython取引ボット生成に特化して優秀との評価があった。

ただし現実的な課題は明確だ。バックテストと実取引のギャップが大きく、取引コスト・スリッページ・市場レジーム変化がパフォーマンスを侵食する。AI取引ボットは「受動的収入源」ではなく「研究・学習プラットフォーム」として機能しているのが現状。FX自動売買システムとしての実践的アーキテクチャは「短期価格変動にML（LSTM・GBM）、ニュースフィルタリングにLLM、戦略最適化に強化学習」の組み合わせが有望で、LLMコスト（損益分岐点への影響）を意識した設計が必要。「AI予測はシグナルの一つとして扱い、リスク管理ツールとして位置づける」という実践的結論は、現行MT5システムの設計判断と一致する。[LLM Trading 2026](https://coinedition.com/llm-trading-in-2026-can-ai-agents-actually-outperform-humans/) / [AI×FX最前線](https://financialsynapse.com/ai-fx-llm-forcast/)
