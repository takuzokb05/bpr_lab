## Claude Code・エコシステム

### ループ設計の公式整理とコスト最適化パターン

Claude Code チーム（ClaudeDevs）が「ループ設計入門」を公開し（14,000 いいね）、ループを 3 種に分類した。①Turn-based：ユーザーのプロンプトで起動し、完了と判断すると停止。SKILL.md に検証ロジックを書き込むと自己検証でターン数を削減できる。②Goal-based（`/goal`）：evaluator モデルが定量的な終了条件（テスト通過数・スコア閾値）を判定し、未達なら差し戻す。③Time-based（`/loop`・`/schedule`）：定期またはイベント駆動で起動し、PR マージやキュー空で終了する。「最もシンプルな解から始め、選択的に使う」という指針は、このリポジトリのリモートトリガー設計にそのまま当てはまる。[原文](https://x.com/claudedevs/status/2074208949205881033)

同日、ClaudeDevs はコスト最適化パターンとして「Fable 5 を advisor（助言役）として使う」構成も紹介した（17,000 いいね）。実行役には安価な Sonnet 5 を据え、判断に迷う要所だけ Fable 5 をスポット呼び出しする 2 層構成で、トークン大部分を低単価で消化しながら重要判断の質を保つ。個人ユーザー向けには beku_AI が同じ思想を「作業の重さで 4 モデルを振り分ける」運用として実践例を示し、67% のトークン削減を報告している。軽作業は Haiku、実装は Sonnet、ブラッシュアップは Opus、後戻りしにくい設計判断だけ Fable という分担が基本形だ。[公式パターン](https://x.com/claudedevs/status/2074606058128224365) / [個人実践](https://x.com/beku_ai/status/2073731796819464256)

### レビュー駆動ワークフローと自己改善エージェント

OSS プラグイン「reviewable-html-workbench」が公開された。AI が生成した HTML に Notion 風のインラインコメントを付け、そのコメントをエージェントが読んで修正するというレビュー→修正ループをローカル完結で実現する。Claude Code・Codex CLI 両対応。[GitHub](https://github.com/u-ichi/reviewable-html-workbench) / [ポスト](https://x.com/u1/status/2065832522198761650)

自己改善型エージェントの設計論として、STATE.md による状態永続化・検証ループでエラーを学習資産化・有効パターンをスキルとして自動蓄積する 3 点が核として整理されている。改善を 4 レベル（プロンプト修正→ツール選択→ワークフロー並列化→スキル自律生成）で段階整理した記事は、このリポジトリの CLAUDE.md・Skills 運用を体系的に見直す指針として使える。[記事](https://x.com/claudecode84/status/2072546601789428152)

モデル移行期の実務知見として、「今の高性能モデルに、チャット内で確立した暗黙のルールや手順を引き継ぎ書として書かせる」という提案も出ている。長い会話を整理して言語化するのは高性能モデルの得意分野であり、CLAUDE.md や Skills への暗黙知明文化の動機付けとして有用だ。[記事](https://x.com/noel_ai_lab/status/2073039341992194336)

### Claude Code の業務活用と Hooks・MCP 解説

GoPenAI が Hooks と MCP の役割分担を整理した。MCP は Claude が到達できる外部ツールを拡張し、Hooks はそのライフサイクル全体（セッション開始・ツール使用・プロンプト送信・コンパクション）で動作を制御する別レイヤーだ。2026 年プロダクション基準は「固定ソース＋制限的 Hooks＋プロジェクト別サンドボックス」の 3 層とされている。[記事](https://blog.gopenai.com/hooks-and-mcp-for-claude-code-7c535374cdf7)

日本語圏では非エンジニア向け活用事例が複数出ている。共通するメッセージは「日本語で指示できれば十分、コーディング不要」で、請求書照合 4.5h→35 分、営業資料 60 分→8 分といった定量成果が示されている。MCP サーバーカタログ 113 選（国内最大規模）も公開されており、Playwright MCP（30,000 スター）や Anthropic 製 9 本のクリエイティブコネクターが注目されている。なお 2026 年 4 月に OX Security が stdio トランスポートの RCE 脆弱性を開示しており（全言語 SDK 対象）、MCP 導入時のセキュリティ確認は必須だ。

## AIニュース・業界動向

### エージェント規制の外枠が動き始めた

米上院議員 Mark Warner が AI AGENT Act 草案を公表した（**一次ソース確認済み**、2026-06-29）。FTC が「信頼・安全な AI エージェント」の連邦認定レジストリを作成・公開し、認定外エージェントによる消費者被害への責任規定と、プラットフォームによる認定エージェントへのアクセス差別を禁止するという内容だ。現在はディスカッションドラフト段階で業界フィードバックを収集中。金融・医療・法律でエージェントが消費者代理で決定を行う「エージェント経済」を前提に設計されており、今後の実装段階でエージェント開発の制約になる可能性がある。[Senate.gov](https://www.warner.senate.gov/newsroom/press-releases/warner-unveils-discussion-draft-of-legislation-to-create-innovative-market-for-secure-artificial-intelligence-agents/)

EU 側では AI Act 高リスクシステムの義務適用が事実上 2 年延期された（**一次ソース確認済み**）。EU 理事会が 2026-06-29 に Omnibus VII 簡素化を最終承認し、スタンドアローン型の義務適用は 2027 年 12 月、製品組み込み型は 2028 年 8 月に変更された。「規制コストが競争力を損なう」という産業界の訴えを受けた現実化路線への転換で、EU 市場でのエージェント展開計画を見直す企業に直接影響する。[EU Council](https://www.consilium.europa.eu/en/press/press-releases/2026/06/29/artificial-intelligence-council-gives-final-green-light-to-simplify-and-streamline-rules/)

主要モデルの現状は「平均 3 日に 1 本の新モデルリリース」ペースで推移。Claude 系は Fable 5（エージェント向け最高性能）・Sonnet 5（エージェント特化・8 月末割引予定）・Opus 4.8（SWE-bench 88.6%）・Haiku 4.5（低コスト）の 4 本立て。GPT-5.6（3 サイズ・コンテキスト 100 万トークン）や Gemini 3.5 Flash も並走している。選択基準として「コスト対性能」と「エージェント対話型か否か」の 2 軸が推奨されている。

## AIトレーディング

### MT5 が MCP ネイティブ対応、FX×LLM 統合の敷居が下がった

MetaQuotes が MT5 Beta Build 5955 を公開し、MCP と AI エージェントのビルトインサポートを追加した（**一次ソース確認済み**、さらに Build 6030 で AI 統合を拡張済み）。クライアントターミナルと MetaEditor 両方で利用でき、AI エージェントが自然言語でマーケットデータ取得・注文発注・ポジション管理・テクニカル分析を統合できるようになった。従来はコミュニティ製 MCP Server での回避策が必要だったが、公式実装により信頼性が向上した。FX 自動取引に LLM を組み込む実験に着手しやすい環境が整ってきた。[mql5.com](https://www.mql5.com/en/forum/511825)

ブローカー側でも Webull・Deriv・IG・eToro 等が AIエージェント向け MCP 対応 API を公開する競争が加速しており、Robinhood は 2026 年 5 月に AI エージェントの証券口座直接接続を発表した（CEO「agentic finance の始まり」）。先行組はリサーチ・ニュース解析・テクニカル分析・注文執行を統合するワークフローを構築中だが、認証・権限設計なしのエージェント接続は不正アクセスや意図しない大量注文のリスクがあると LeapRate は警告している。[LeapRate](https://www.leaprate.com/technology/broker-mcp-ai-agent-trading-infrastructure-race-2026/)

一方、学術面では 2026 年 5 月の arxiv 論文（2605.28359）が LLM の「遂行ギャップ」を定量化した。LLM は市場知識を持っていても実際の取引判断への変換が弱く、累積リターンの大部分は市場・スタイル露出で説明でき、株式選択アルファの持続的証拠は限定的だという結果だ。「完全自律の意思決定者ではなく監督下のリサーチアシスタント」という位置付けが現時点での適切な期待値設定として提示されている。OSS の LLM 取引ボット（バックテスト付き）も公開されているが研究・学習目的と明記されており、本番資金への直接適用は非推奨とされている。
