## Claude Code・エコシステム

### July 2026アップデートと新機能

Claude Codeの7月アップデートは機能の幅と深さの両面で節目となった。最大の変化は `/fork` コマンドで、セッションをブランチしてリスクなく実験的な変更を試せるようになった。合わせて `/doctor`（環境診断）、公開アーティファクト共有、エディタロール（チーム内の権限分離）、BroadcastAutoMode（Bedrock・GCP・Microsoft Foundry対応拡大）が追加。Cowork はWebとモバイルにGA拡大し、ラップトップを閉じても継続するリモートセッションがベータとなった。[^1][^3]

### モデル選択の新しい基準（一次ソース確認済み）

Sonnet 5（6/30リリース）がClaude Codeのデフォルトモデルに移行した。SWE-bench 72.7%・Terminal-bench 76.1%は複数ソースで確認済み。Opus 5（7/24リリース）はFrontier-Bench v0.1で全モデル首位（43.3%）を達成し、Fable 5と約10pt差でありながら半額という破格の位置づけとなった。実用選択基準は「日常コーディング・PRレビュー → Sonnet 5（$2/$10、8/31まで促販）、最難度推論・長期自律エージェント → Opus 5」。[^13]

### CLI完全ガイドとベストプラクティス

2026年7月に相次いで公開されたClaude Code実践ガイド群は、MCP・Hooks（17イベント4タイプ）・Skillsの三層構造を体系的に解説している。「CLAUDE.md 200行以下・HTMLコメントによるコンテキスト節約・git worktreeを使ったサブエージェント並列実行」の組み合わせが、5〜10倍の開発スループット向上事例で共通して登場する実践知として浮かび上がった。非エンジニアを含む新規ユーザーへの推奨第一スキルはContext7（古いLLM知識の補完）。[^2][^4][^5]

### Agent SDKとMCPのアーキテクチャ変化

Claude Agent SDK（旧Claude Code SDK）は2026/6/15から課金体系が変更され、非インタラクティブ実行（`claude -p`・CI/CD・バックグラウンドエージェント）がインタラクティブ制限とは別の月次クレジットから消費される。スケジュール済み自動実行タスクは事前のクレジット消費量確認が必要。[^7]

MCP 2026公式ロードマップはステートレス化を最重点課題に据えた。現行のセッション状態依存アーキテクチャがロードバランサー背後での水平スケーリングを阻んでいる問題を、プロトコルレベルのセッション再開・マイグレーション標準化で解消する計画。Extensions・Tasks・MCP Apps・OAuth 2.1強化も今後の実装ロードマップに含まれる。[^8]

## AIニュース・業界動向

### 8月のモデルリリース競争

DeepSeek-V4-Flash・GPT-5.6 Luna（OpenAI、80%値下げ）・Meta Muse Spark 1.1と、8月に入ってもモデルリリースが週次ペースで続いている。GPT-4レベル性能を大幅低コストで提供する効率改善競争が核心的なトレンドで、個別リリースへの過熱より「タスク特化性能・API単価・スイッチングコスト」での実用評価が実務上の正解となっている。[^14]

### EU AI法 GPAI執行フェーズへ（本日 8/2、一次ソース確認済み）

本日（2026年8月2日）より、EU AI法のGPAI（汎用AIモデル）に対する罰則・執行権限が発動する。違反時は年間グローバル売上3%またはユーロ1,500万以上。義務自体は2025/8から適用済みだったが、執行権限はこの日が初日。高リスクAI適用はDigital Omnibus法案で2027/12以降に延期される方向だが法的には8/2スケジュールが依然有効。EU向けサービス提供企業はGPAI義務への即時対応が必要。[^15]

## AIトレーディング

2026年、AIトレーディングエージェントをめぐる議論は「賢い≠安全」という認識に収束しつつある。Botは確定的ルール実行でバックテスト可能・説明容易だが、エージェントは自律判断でバックテストが困難で動作説明も難しい。複数の実験データ（オープンソースLLMエージェント6ヶ月ライブテスト）では、株式・仮想通貨ともSharpe ratioがベンチマーク以下のケースが多数。実際に収益を上げているシステムは情報優位（機関レベルのオルタナデータ）か好調市場窓の恩恵であり、一般開発者が再現できる条件ではないとの見解が複数ソースで一致した。[^10][^11]

MT5での実装面では、LLMを「認知的判断エンジン」として機能させる構成（MT5でシグナル生成→LLMで意思決定→MT5で執行）が実装例として紹介された。VPS稼働・レイテンシ100ms以下推奨といった実運用ポイントも整理されている。「一貫性・タイミング・規律の向上目的」という半自律モデルが2026年の合意的推奨とされており、FX自動取引を運用中のユーザーにとってすでに実践中のアプローチとの整合が高い。[^12]
