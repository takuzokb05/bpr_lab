## Claude Code・エコシステム

### v2.1.261 と `/skill-doctor` — スキル管理が正式ワークフローに

Claude Code v2.1.261（2026年9月4日リリース）でついに `/skill-doctor` コマンドが追加された（一次ソース確認済み）。
読み込んでいるスキルのうち未使用のもの・コンテキストコスト過大なものを特定・剪定できる診断ツールで、
スキルが10本以上に積み上がったこのリポジトリには直接刺さる機能だ。

同バージョンでは組織ポリシー診断も強化された。`/status` と `claude doctor` に「Organization policy」行が追加され、
プロキシ非対応等でポリシーが読み込めない理由を可視化できる。リモートセッション運用でポリシーの読み込み失敗に悩んでいた場合、
この行を見れば根因が掴める。また `bashOutputMaxChars`・`taskOutputMaxChars` 設定で出力上限を最大128K文字まで引き上げられるようになり、
長大なコマンド出力を切り捨てずに取り扱う場面で役立つ。

### 8月の大型アップデート群 — Fork Mode・Auto Mode・クロスセッション

8月を振り返ると、個人ユーザーに大きな影響をもたらした変更が3つある。

**Auto mode** が 2026-08-14 から Pro/Max/Team のデフォルトになった。コスト効率と出力品質を自動調整するモードで、
従来の手動モデル切り替えをシステムが肩代わりする。**Fork mode** もデフォルト on となり、
バックグラウンドサブエージェントにサイドタスクを委譲しながらメインセッションをブロックしない並列処理が標準化された。
そして **Cross-session messaging**（`SendMessage` ツール経由）で、別セッションのエージェントに指示を送れるようになった点は
マルチエージェントワークフロー設計の自由度を大幅に広げる。

日常的にスケジュールタスクと手動セッションを並走させる運用では、Fork mode + Cross-session の組み合わせで
「スケジュールタスクの途中経過をメインセッションに引き渡す」構成が現実的になってきた。

### セキュリティと Skills 活用 — 同じ週の2本が語る同一テーマ

今週は「Claude Code の正しい使い方」をテーマにした記事が2本集まった。

**セキュリティ観点（General Analysis）** は、CLAUDE.md に書いたルールはエージェントが意図せず上書きする可能性があると明言し、
真のガードレールは settings.json や hooks で実装すべきと主張する。
MCP には allowed_domains/blocked_domains による明示的なドメイン制限、hooks には pytest・SQLfluff の自動実行を組み込む構成が推奨されている。
9月に Anthropic が web_search/web_fetch ツールへドメイン制限機能を追加したと述べており、
このリポジトリの「ホワイトリスト外は403」という現状設定の背景と一致する。

**Skills 日本語入門（Cloud for All）** は、CLAUDE.md の「常に適用するルール」と Skills の「特定作業時のみ必要な手順」の使い分けを基本原則として整理している。
セキュリティ記事と組み合わせると「CLAUDE.md はコンテキスト補助・Skills は手順書、強制力はsettings.json+hooks」という三層モデルが浮かび上がる。
この整理は現リポジトリの設計にそのまま当てはまる。

> セキュリティ: [generalanalysis.com](https://generalanalysis.com/guides/anthropic-claude-code-security-best-practices)  
> Skills入門: [cloud-for-all.com](https://www.cloud-for-all.com/blog/what-is-claude-code-skill)

### データエンジニア向けガイドと MCP 2026-07-28

**データエンジニア向け Claude Code ガイド（The Pipe and the Line）** は FX 自動取引のデータパイプライン文脈でも読み替えられる。
MCP 経由で BigQuery・Snowflake・Redshift に直結してSQL生成の精度を上げる手法、
dbt プロジェクトへの自動テスト（pytest-dbt）・linting（SQLfluff）の hooks 組み込みは、
取引履歴・ポジション管理データを扱うスクリプト群へほぼそのまま応用できる。

**MCP 2026-07-28 仕様** のステートレス化は、インフラ設計に直結する変更だ。セッションと初期化ハンドシェイクの廃止により
水平スケーリングが簡素化され、ゲートウェイ側の DPI が不要になった。ステートフルな自作 MCP サーバーを持っている場合は
リファクタリングコストを見積もる必要があるが、ステートレス設計済みであれば追加コストはほぼゼロ。
Multi Round-Trip Requests の追加で長時間エージェントタスクへの対応も向上している。

> データエンジニア: [thepipeandtheline.substack.com](https://thepipeandtheline.substack.com/p/intro-claude-code-for-data-engineers)  
> MCP移行: [aaif.io](https://aaif.io/blog/mcp-2026-07-28-whats-changing-and-how-to-migrate)

## AIニュース・業界動向

### EU AI Act — 「予告」から「執行」へ（一次ソース確認済み）

2026年8月2日から透明性義務と EU AI Office の執行権限が発効し、9月からは欧州 AI Office と24カ国の市場監視当局が
第1回コンプライアンス検査を開始した。優先検査は HR（自動履歴書スクリーニング）・小売銀行（信用審査 AI）・
民間医療（AI トリアージ）の3分野に集中している。

日本の公務員組織が欧州向けに AI サービスを提供するケースはまだ少ないが、
民間委託先やベンダーが EU 規制圏のサービスに関与する場合は9月の第1波が直接リスクになる。
高リスクシステムの本格義務（Article 11）はスタンドアロン系が2027-12、規制製品組み込み系が2028-08まで猶予があるが、
透明性ルールは「現在進行形」で執行中だ。
Anthropic は8月2日以降のモデル出力にウォーターマークと検出 API（プライベートプレビュー）で対応している。

> [legalnodes.com](https://www.legalnodes.com/article/eu-ai-act-2026-updates-compliance-requirements-and-business-risks)
