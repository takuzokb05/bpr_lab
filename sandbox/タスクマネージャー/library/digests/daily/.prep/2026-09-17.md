## Claude Code・エコシステム

### 拡張メカニズム三者の使い分け：今週の結論

3 本の独立した記事が同日に「Hooks vs Skills vs Subagents vs CLAUDE.md」を論じ、核心フレームワークの収束が確認できた。

AINexusDailyの記事 は「**Hooks は決定を取り除く、Skills は決定を追加する、Subagents は決定を隔離する**」という一文で三者を整理する。BuildThisNow.com はトークンコストという別軸で補完する：Skills の初期オーバーヘッドは約 100 トークン（名前と説明のみ）に対し、Subagents は約 20,000 トークンの生成コストを持つ。DEV.io の実践ワークフロー記事は「インフラとして使う人 vs チャットボットとして使う人」の格差拡大を指摘し、自動ロードされるファイル・タスク連動で発火する Skills・夜間に走るワークフローを構築した人が加速していると述べる。

重要な落とし穴として AINexusDailyが強調するのは「**always（常に）要件を when relevant（関連する場合）として実装するミス**」。Hooks は強制、Skills は勧告、この非対称が実行時に正反対の挙動を生む。日本語での解説としては UnionAI の記事が概念から実務カテゴリまでをカバーし、10 時間 → 30 分に削減できたとする事例を紹介している。

### Fable 5.1 の破壊的変更 3 件（一次ソース確認済み）

2026-09-01 に GA した Claude Fable 5.1 の移行必須ポイント。**forced tool use（tool_choice: any/tool）が廃止**され 400 エラーになった点は即時影響が大きい。thinking block はモデル固有化されたため会話履歴をまたぐモデル切り替えに注意が必要で、append-only 管理が必須になる。cache reads は $1.00 → $0.25/MTok と 75% 値下げされた。

注意：「Fable 5.1 の thinking block は旧モデルで読み取り不可」という記述が一部記事に存在するが、正確には逆方向—「旧モデルが Fable 5.1 の thinking block を読めない」が正しい。

移行手順: (1) model ID を claude-fable-5-1 に更新 → (2) forced tool use を削除 → (3) thinking block を append-only 管理 → (4) effort 再調整 → (5) eval 再実施。

- [Fable 5.1 公式 What's New](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1)

### MCP プロトコルのステートレス化（一次ソース確認済み）

2026-07-28 仕様の MCP 大型更新でアーキテクチャが根本的に変わった。**ステートフル（セッション維持必須）→ ステートレス（各リクエストが自己完結）**に移行したことで、スティッキーセッション＋共有セッションストアなしで普通のロードバランサーの後段にサーバーを置けるようになった。`Mcp-Method` / `Mcp-Name` HTTP ヘッダーによりゲートウェイが直接ルーティング・認可を実行できる。

月間 SDKダウンロード 9,700 万回超（Python+TypeScript 合計）・廃止コンポーネント 12 ヶ月動作保証。TypeScript・Python・Go・C# の SDK も v2 に更新済み。Agentic AI Foundation（Linux Foundation 傘下）がガバナンスを担う。

- [ITdailyの解説](https://itdaily.com/news/software/mcp-2026-update-specs/)

## AIニュース・業界動向

### 9 月初旬の新ツール群：GitHub HydraFusion が目を引く

2026-09-03〜04 にかけて複数の AI エージェントインフラが集中リリースされた（一次ソース確認済み）。

最も実用的なのは **GitHub HydraFusion**（2026-09-04 research preview）。GitHub 公式のマルチモデルオーケストレーション機能で、Single / Cascade（低コストモデルから必要時エスカレーション）/ Critique（ピアレビューサイクル）の 3 パターンを持つ。TerminalBench 2.1 で Claude Opus 5 と比べ 67% のトークンコスト削減かつ 4.9 ポイント上回る結果が報告された。GitHub に直接組み込まれる点で今後の普及が最も速いと見られる。

他にも MCP サーバー提供型のロケーションインフラ Mireye（YC S2026）、オープンソースのマルチエージェント MagiCrew、ガバナンス機能付きゲートウェイ ARBR など MCP 対応ツールの急増が目立つ。

## AI トレーディング

2026 年版のエージェント型 AI 取引の包括ガイドが AllAboutAI から公開された。2026 年に「自律稼働」が現実になった背景として挙げられるのは、推論モデルの長時間ドリフト解消・サブエージェントの低コスト化・Hyperliquid/Polymarket/Robinhood の MCP アクセス拡大の三点。

提示される 4 層アーキテクチャは (1) ペルソナ/戦略文書 → (2) リサーチスキル（並列サブエージェント）→ (3) 実行モデル → (4) ハートビートモニター（30〜120 秒ループ）。実際の数字として初期資本 $30〜200・月額サブスク $220・週$100 の趣味運用という水準が示されている。

主なリスクとして指摘されているのはループの途中自己終了と、HyperliquidのHIP-3 DEX ルーティングのようなサイレント破損。分散がショートタイムフレームを支配するため、戦略検証には数百回の取引が必要とされる。なお、Codex 5.5 が Claude Opus よりヘッドトゥヘッドテストで優位としているが、fact check 未実施のため参考値として扱うこと。
