## Claude Code・エコシステム

### v2.1.237：ANTHROPIC_DEFAULT_MODEL と Concise出力スタイル（一次ソース確認済み）

DevelopersIO が2本のアップデートをまとめた解説から、実運用に直結する2点が際立つ。

**ANTHROPIC_DEFAULT_MODEL**（v2.1.236追加）は、新セッション開始時のデフォルトモデルを環境変数で固定する仕組み。
既存の `ANTHROPIC_MODEL` との違いは「永続性」で、`/model` コマンドで都度上書きできる一方、
再起動後も設定が維持される。複数モデルを使い分けながら「普段はこのモデルで」という基準が欲しい場合に有効だ。

**Concise出力スタイル**（v2.1.237追加）は、前置きと実況コメントを省いて結果を先頭に出力するスタイル変更。
思考の深さや作業品質は変わらず、「で、何ができたの？」という情報密度が上がる。
explainx.ai の詳細ガイドによれば、設定には2つの罠がある。

- **`/config` はカレントプロジェクト限定**。グローバルに効かせるには `settings.json` を直接編集する必要がある
- **`/clear` または新セッション開始後**に有効化される（即時反映ではない）

Boris Cherny が「band aid」と表現した点も見逃せない。
つまりこれは暫定措置であり、将来的により根本的な出力制御改善が来ることを示唆している。

また、claude-api スキルのコンテキスト削減（200K→25K）は長期セッション時のコスト改善として実質的な恩恵が大きい。
LLMゲートウェイ経由のプロンプトキャッシュ修正も、カスタム環境利用者には重要な bugfix。

## AIトレーディング

### MT5 × LLM 連携：3つのアーキテクチャ比較（未検証記事）

hedgrow media による日本語実装ガイドは、MT5とClaude/GPTを繋ぐ3方式を体系的に整理している。
自動売買プロジェクトの「LLM組み込み設計」を検討するタイミングで参照できる一次情報。

3アーキテクチャの概要：

1. **ファイルベース連携**（MQL5 ↔ テキストファイル ↔ Python ↔ LLM API）：
   実装が最も簡単で、MQL5スキル不要。レイテンシが高い。検証・プロトタイプ向け。

2. **Pythonミドルウェア**（MQL5 ↔ Socket ↔ Python Server ↔ LLM API）：
   リアルタイム性が向上し、複雑なロジックを Python 側で持てる。本番移行の現実的な選択肢。

3. **直接MQL5実装**（MQL5内でHTTPリクエスト ↔ LLM API）：
   レイテンシ最小だが、MQL5の深い知識が必要。メンテナンスコストが高い。

注意点として、LLMの判断をそのままトレードに反映する構成はバックテストが難しい。
「LLMで戦略候補を絞り → ルールベースで実行判断」という分業が堅実とされている。
また API キー管理（MT5端末内への平文保存は危険）にも言及あり。

- [hedgrow media MT5×LLM連携ガイド](https://media.hedgrow.io/ja/fx/articles/llm-fx-api-mt5-renkei)
