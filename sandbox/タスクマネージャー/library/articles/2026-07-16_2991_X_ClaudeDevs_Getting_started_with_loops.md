## 投稿内容
X Article（長文・Claude Code チーム公式）。「プロンプトする」のではなく「ループを設計する」という考え方を、ループの分類軸（起動方法／停止条件／使用する Claude Code プリミティブ／適したタスク）で整理。
- Turn-based loop: ユーザーのプロンプトで起動、Claudeが完了/追加コンテキスト要と判断で停止。短い単発タスク向け。検証を SKILL.md に符号化し自己検証を強化するとターン数を削減できる（検証は定量的なほど良い）
- Goal-based loop（/goal）: 手動起動、ゴール達成 or 最大ターン到達で停止。検証可能な終了条件を持つタスク向け。evaluatorモデルが条件を満たすまで差し戻す。テスト通過数やスコア閾値など決定的基準が有効
- Time-based loop（/loop・/schedule）: 時間間隔で起動、キャンセル/完了（PRマージ・キュー空）で停止。定期業務や外部システム連携向け。間隔を長めに/時間ではなくイベント駆動にして消費管理
- 「すべてのタスクに複雑なループが要るわけではない。最もシンプルな解から始め選択的に使う」

## 要約
Claude Code 公式による「ループ設計」の定義と使い分け。ループ=停止条件を満たすまで作業サイクルを繰り返すエージェント、として3種を整理: ①Turn-based（対話1往復・SKILL.md で自己検証強化）②Goal-based /goal（evaluatorが決定的な終了条件を判定し差し戻す）③Time-based /loop・/schedule（定期/イベント駆動、PRマージ等で終了）。停止条件を定量的・決定的にするほど早期終了や暴走を防げるのが一貫した原則。1.4万いいねの公式一次情報で、当リポジトリのリモートトリガー/スケジュール運用の設計指針に直結する。
