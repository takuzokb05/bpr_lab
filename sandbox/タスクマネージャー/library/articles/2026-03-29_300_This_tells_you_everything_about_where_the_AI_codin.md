## 投稿内容

This tells you everything about where the AI coding war is actually being fought.

OpenAI already supports MCP in Codex. Anthropic created MCP as an open standard, and Claude Code, Cursor, Windsurf, and dozens of other tools connect to the same servers through the same protocol. You can wire up Slack, Figma, Notion, GitHub, and hundreds more through MCP today, on any agent that speaks the protocol.

So why is OpenAI announcing "plugins"?

Because the integration layer is the lock-in layer.

MCP is open. Anyone can connect to anything. That's great for developers but terrible for platform economics. Plugins give OpenAI a curated, first-party experience they control: discovery, installation, permissions, and the update cycle. The difference between "connect any MCP server" and "install a plugin from our marketplace" is the difference between an open bazaar and a walled app store.

Over 1 million developers use Codex weekly. Usage is up 400%+ since January. If OpenAI becomes the place where you manage your Linear issues, review your Figma designs, read your Slack threads, query your Stripe dashboard, and push to GitHub, all from one prompt box, they've built something stickier than a code completion engine. They've built a developer operating system.

The prompt in that screenshot says it all. "Summarize project from Notion, generate a design from Figma, and send an update in Slack." That's three SaaS products orchestrated through one interface. The coding agent becomes the connective tissue between every tool in your stack.

Claude Code does this through MCP today. Cursor does it. The protocol is open and the ecosystem is massive. But OpenAI is betting that most developers won't configure MCP servers manually. They'll click "install" on a plugin and never look back.

The real product here is the default. Whoever becomes the coding agent developers open first owns the integration surface. And whoever owns the integration surface owns the workflow.

That's the fight. Not models. Not benchmarks. Distribution into the developer's daily loop.
