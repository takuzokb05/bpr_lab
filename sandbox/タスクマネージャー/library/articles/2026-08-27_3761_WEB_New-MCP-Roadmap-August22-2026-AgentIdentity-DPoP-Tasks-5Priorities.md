# The New MCP Roadmap (August 22, 2026): Agent Identity, DPoP Security, 5 Priorities

## 投稿内容
The MCP Core Maintainers published an updated roadmap on August 22, 2026, five weeks after the 2026-07-28 specification turned remote MCP servers into ordinary HTTP workloads. The roadmap names the 5 areas that Working Groups will prioritize next:

1. Agentic Messaging Primitives: Tasks, subscriptions, progress notifications for longer-running loops and streamed results
2. HTTP-Native Transport Unification: Standardizing HTTP-based transports including local stdio servers
3. Agent Identity & Enterprise Security: DPoP (Demonstrating Proof of Possession) + Workload Identity Federation to replace API keys
4. Improved Primitives: Clarify tool result handling, progressive discovery so servers don't overwhelm models
5. SDK Developer Experience: Ergonomics, spec conformance, documentation across all platforms

Context: The previous roadmap's priorities largely landed in the 2026-07-28 release (stateless, self-describing, horizontal scaling). Formal Contributor Ladder, Working Groups, and SEP (Specification Enhancement Proposals) process now active.

## 要約
MCPコアメンテナーが2026年8月22日に新ロードマップを公開。2026-07-28スペック（ステートレスコア・HTTP単一トランスポート）の5週間後。次期フォーカス5領域：(1)エージェントメッセージングプリミティブ（Tasks・サブスクリプション、長期ループ・ストリーミングに対応）、(2)HTTP-NativeトランスポートUnification（stidoとリモートの統一）、(3)エージェントID・エンタープライズセキュリティ（DPoP + Workload Identity FederationでAPIキーを廃止する方向へ）、(4)ツール結果処理明確化・プログレッシブディスカバリ（モデルに全カタログを押しつけない）、(5)SDK開発者体験向上（仕様準拠・ドキュメント改善）。コントリビューターラダー・ワーキンググループ・SEP制度が機能し始め、MCPのガバナンス成熟化が進む。FX自動取引でMCPサーバーを活用する際、(3)のDPoP認証対応が重要になる見込み。
