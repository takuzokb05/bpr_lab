# /research-cc — Claude Code リサーチスキル

## 概要

指定テーマについてClaude CodeのベストプラクティスをWeb調査し、`library/catalog.md` のエントリ形式で結果を返す。図書館の司書が使う専用リサーチツール。

## 入力

ユーザーからテーマを受け取る。例:
- 「Hooksの最新活用事例」
- 「非エンジニアの成功パターン」
- 「Agent Teamsのベストプラクティス」
- 「CLAUDE.mdの書き方 2026最新」

テーマが曖昧な場合は、以下の切り口を提案して絞り込む:
- 特定の機能（Hooks / MCP / Skills / Agent Teams / Worktree 等）
- 特定のユーザー層（非エンジニア / PM / デザイナー / バックエンドエンジニア 等）
- 特定の課題（コスト削減 / 品質向上 / コンテキスト管理 / 並列作業 等）

## プロセス

### Step 1: 多角的検索（3回以上）

以下の軸で最低3回検索する。同じ情報源に偏らないこと。

| # | 検索軸 | 例 |
|---|--------|---|
| 1 | 英語 + テーマ | `Claude Code {theme} best practices 2026` |
| 2 | 日本語 + テーマ | `Claude Code {テーマ} ベストプラクティス 2026` |
| 3 | 公式ソース | `site:code.claude.com {theme}` or `site:anthropic.com {theme}` |
| 4 | （任意）コミュニティ | `site:github.com claude-code {theme}` |

**検索年指定**: 必ず `2026` を含める。古い記事（2024以前）は参考程度に留める。

### Step 2: 記事の読み込みと要点抽出

検索結果から有用な記事を選び（3〜6本）、WebFetchで読み込む。

各記事から抽出する項目:
- **核心的な知見**（1-2行）
- **具体的な手法・設定例**（あれば）
- **タスクマネージャー/Skills/エージェントに反映すべきポイント**（あれば）
- **ソースURL**

### Step 3: library/catalog.md エントリの生成

以下の形式で出力する。ユーザーが承認したら `library/inbox/` にテキストファイルとして保存し、`library/catalog.md` にエントリを追加する。

```markdown
## 調査結果: {テーマ}

調査日: YYYY-MM-DD
検索回数: N回
読み込み記事数: N本

### 発見した記事

#### 1. {記事タイトル}
- **要点**: （1-2行）
- **具体的手法**: （あれば）
- **反映候補**: （タスクマネージャーのどこに反映すべきか）
- **ソース**: [タイトル](URL)

#### 2. {記事タイトル}
...

### library/catalog.md 追加エントリ（案）

| # | タイトル | ファイル | 分類 | 要点 | 反映先 | 状態 |
|---|---------|---------|------|------|--------|------|
| N | ... | `articles/...` | ... | ... | ... | 読了 |

### タスクマネージャーへの反映提案

- **反映すべき**: （具体的に何をどこに）
- **検討の余地あり**: （中期的に検討すべきこと）
- **不要**: （既に反映済み or 対象外の理由）
```

### Step 4: ユーザー承認と反映

1. Step 3 の出力をユーザーに提示する
2. 承認されたら:
   - 有用な記事を `library/inbox/` にテキストファイルとして保存（記事要約 + ソースURL）
   - `library/catalog.md` にエントリを追加（状態=読了）
3. タスクマネージャーへの反映が承認された場合:
   - 対象ファイルを編集
   - `library/catalog.md` の状態を「反映済」に更新

## 信頼性ルール

- **公式ドキュメント優先**: code.claude.com > anthropic.com > 有名テックブログ > 個人ブログ
- **鮮度重視**: 2026年の記事 > 2025年後半 > それ以前（Claude Codeは進化が速い）
- **実体験ベース優先**: 「使ってみた」記事 > 理論・解説記事
- **矛盾する情報**: 両方提示し、公式ドキュメントに近い方を推奨
- **ハルシネーション防止**: 検索結果にない情報を追加しない。推測は明示する

## Gotchas

- `site:` 検索はGoogleのみ有効。WebSearchでは通常のキーワード検索にフォールバックする
- zenn.dev / note.com の記事はWebFetchでページ全体が取れないことがある。要点が取れなければ検索結果のスニペットから判断
- 「Claude Code」と「Claude」を混同しない。Claude Code はCLI/エージェントツール、Claude はLLM本体。検索時に区別する
- 英語記事の方が情報が早い（公式ブログは英語先行）。日本語記事は実践知見が多い。両方必要
- 1テーマにつき記事6本以上読むとコンテキストを圧迫する。3〜5本で十分

## 検索で学んだノウハウ（運用しながら追記）

- **効果的な検索キーワード**: `"Claude Code" best practices 2026`, `Claude Code非エンジニア 活用`, `"CLAUDE.md" tips`
- **高品質ソース**: zenn.dev（日本語実践知見）、Anthropic公式ブログ（権威）、note.com（非エンジニア事例）
- **避けるべきソース**: SEOスパム的な「完全ガイド」記事（内容が薄い）、6ヶ月以上前のバージョン固有Tips
- **非エンジニア調査時**: `非エンジニア`, `ノーコード`, `業務自動化` を組み合わせると精度が上がる
