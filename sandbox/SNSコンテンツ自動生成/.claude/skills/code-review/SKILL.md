# Code Review - 多角的コードレビュー

## 概要

コードを堅牢性・効率性・セキュリティ・保守性の4つの観点から体系的にレビューし、重大度分類付きの改善提案を行うスキル。

**対象**: あらゆる言語・フレームワークのコードレビュー
**キーワード**: コードレビュー, 品質改善, セキュリティ, リファクタリング

## コアプロセス

### 1. スコープ確認
- 対象ファイル・関数・変更差分の範囲
- プロジェクトの技術スタック・アーキテクチャ
- 変更の目的

### 2. 4観点チェックリスト走査

#### 観点A: 堅牢性（Robustness）
- エラーハンドリング、エッジケース、入力バリデーション、リソース管理、並行処理

#### 観点B: 効率性（Efficiency）
- アルゴリズム計算量、DBクエリ、メモリ使用、I/O操作、キャッシュ

#### 観点C: セキュリティ（Security）
- インジェクション対策、認証・認可、機密情報、依存パッケージ脆弱性

#### 観点D: 保守性（Maintainability）
- 命名、責務分離、コード重複、抽象化レベル、テスタビリティ

### 3. 重大度分類

| 重大度 | 基準 | 対応 |
|--------|------|------|
| Critical | セキュリティ脆弱性、データ損失リスク | 即座に修正必須 |
| High | バグの温床、パフォーマンス劣化 | リリース前に修正 |
| Medium | 可読性低下、軽微な非効率 | 次回以降で対応 |
| Low | スタイル、命名の好み | 任意で対応 |

### 4. 改善提案
各指摘に問題の説明・修正前コード・修正後コード・補足を含める。

### 5. 総合評価
観点別の評価（A〜D各5段階）、Critical/High件数、ポジティブフィードバック、優先対応トップ3。

## ルール

1. 指摘には必ず修正例を添える
2. 良い実装も評価する
3. プロジェクト文脈を考慮
4. Lowレベルの大量指摘よりCritical/Highに集中
5. 建設的なトーン

## 注意事項

- 大規模コードベースはディレクトリ単位で分割
- 自動フォーマッターで対処可能な指摘はLowに分類
