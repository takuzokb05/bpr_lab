# Error Handling Audit - エラーハンドリング監査

## 概要

既存コードのエラーハンドリングを6つのカテゴリで体系的に監査し、重大度分類と改善パターンを用いて具体的な修正計画を提示するスキル。

**対象**: Python, JavaScript/TypeScript, その他主要言語
**キーワード**: エラーハンドリング, 例外処理, 信頼性, 監査

## 監査チェックリスト

### カテゴリ1: 例外の握りつぶし（Silent Failures）
空のexcept/catch、passのみ、広すぎる例外キャッチ等を検出

### カテゴリ2: 不適切な例外粒度（Wrong Granularity）
複数の異なる例外の一括処理、ビジネスエラーとシステムエラーの混同等

### カテゴリ3: ユーザー通知不足（Poor User Feedback）
技術的エラーメッセージの直接表示、原因・対処法の欠如等

### カテゴリ4: リソースリーク（Resource Leaks）
finally未使用、コンテキストマネージャ未使用、トランザクション未ロールバック等

### カテゴリ5: リカバリー戦略の不在（No Recovery Strategy）
リトライなし、フォールバック未定義、ロールバック未実装等

### カテゴリ6: セキュリティ上のエラー処理問題（Security Issues）
スタックトレース公開、内部情報漏洩、認証バイパス等

## 改善パターン集

パターン1: APIリトライ（指数バックオフ）
パターン2: トランザクション管理
パターン3: エラーメッセージ変換
パターン4: 構造化ログ

## ルール

1. 全6カテゴリをチェック
2. 重大度を付ける（Critical/High/Medium/Low）
3. 改善パターンを引用
4. 既存の良い実装を壊さない
5. プロジェクトの文脈を考慮

## 注意事項

- 大規模な場合はディレクトリ単位で分割
- セキュリティ指摘は公開PRに書かず別途報告
- Critical→High→Mediumの優先順で段階的改善
