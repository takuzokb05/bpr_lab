## High

**[H-1] 年変更ハンドラの再描画ミスでカレンダータブが二重描画される（バグ+冗長分岐）** — `v2.html:527-535`
`yearSelect` の change は `renderCalendarTab(container.parentNode.querySelector('.tab-content') || container)` を呼ぶが、`renderCalendarTab` は append のみでクリアしないため、年を変えるたびカレンダーUI一式が末尾に複製される。すぐ下の `monthSelect`（542-548）は正しく `renderActiveTab()` を使っており、同目的コードの二重実装がバグ化した典型。**修正**: 年側も `renderActiveTab()` に統一（1行修正）。

**[H-2] 年月変更時の状態リセット不完全（dayTimeSettings / slot.specificDays の持ち越し）** — `527-549` / `364` / `842-848`
`holidays`・`workdayOverrides` はクリアされるが、日番号キーの `calendar.dayTimeSettings`（午前/午後設定）と各枠の `specificDays` はクリアされず、旧月の設定が新月にそのまま適用される（4月の「15日午前のみ」が5月15日にも効く）。**修正**: `resetMonthDependentState()` に集約して両ハンドラから呼ぶ。

**[H-3] `runAutoAssign` 308行・9責務の巨大関数** — `2142-2449`
入力ガード/シャッフル/カウンター初期化/可用率計算/`countFilledSlots`・`assignOne` のループ内クロージャ定義（2259-2306、日数×枠数回再生成）/固定確定/候補ソート/連続回避/スワップ2パス目が同居。CLAUDE.md「1関数1責務」違反、単体テスト不能。**修正**: `computeAvailabilityRatio` / `countFilledSlots` / `assignFixedStaff` / `fillRemainingSlots` / `swapConsecutivePass` 等へ抽出。

**[H-4] スコア関数の完全重複 + コンパレータ内線形探索（200人でO(n²·log n)）** — `2336-2340`（`weightedCount`）と `2421-2427`（`swapWeighted`）
同一式のコピペが2本。かつ両方が内部で `state.staff.find`（O(n)）を呼ぶため、`candidates.sort` の比較のたびに線形探索が走る。200人×枠2×稼働22日で数千万オペ規模になり体感遅延が出得る。同パターンの `find` は `countFilledSlots`(2265)、ペア判定(2376)、`renderGrid`セル描画(1959) など計14箇所。**修正**: 冒頭で `const staffById = new Map(state.staff.map(s=>[s.id,s]))` を構築して全域で使用、スコア関数を1本化、ソート前にスコアを事前計算。

**[H-5] loadData: 破損データを黙って初期化 → 次回保存で復旧不能に上書き** — `379-399`
破損時 `console.error` のみでユーザー通知なし。操作すると `saveData()` が（手修復可能だったかもしれない）元データを初期データで上書きし全損。**修正**: 破損時は生データを `toban_tool_data_broken_backup` へ退避し、日本語アラートで「JSONインポートで復元」を案内。
