## 総合評価

**土台は堅牢、しかし「曜日固定」と「ペア×連続回避」に重大バグあり。**

- ✅ セキュリティ規約（innerHTML/onclick/eval/var禁止等）は**違反ゼロ**。構文エラーなし、通常操作でconsoleエラーゼロ。
- ✅ 時短・公休・不可日・免除・出さない・同日重複・applyMode・境界条件（職員0/枠0/2月/割り当て不能）・公平性（登録順バイアアスなし、spread≤1）・200人性能（186ms）は**すべて実行テストでPASS**。

- ❌ **連続回避スワップがペアを分離**する（ハード制約違反、ストレス15回中14回再現）。
- ⚠️ データ保護が弱い（確認なしの全消去・破損時の無言初期化→上書き全損）。

## 最優先の改善提案（費用対効果順）

### P1: ロジックの重大バグ修正（当番表の正しさに直結）

1. **連続回避スワップが曜日固定職員を退去させる** — スワップ2パス目（v2.html:2386-2443）の退去除外条件がペアのみで曜日固定を見ていない。固定機会の49%で欠落。→ 除外条件に「当該曜日×枠に固定されている職員」を追加
2. **枠ローテーションで固定職員が先行枠に奪われる** — 日ループで固定枠が後回しの日、`getEligibleStaff`（2630-2641）が未確定の固定職員を素通し。26%流出。→ 日ループ冒頭で全枠の曜日固定を先に一括確定
3. **スワップがペアの片割れを単独投入** — 投入側候補（2417）にペア職員が混入し1人分だけ置換。→ 投入候補から `trainingPairId` 持ちを除外
4. **枠削除時に `staff[].fixedDays` の参照が残置**（789行）— 実データで発生済み。→ 枠削除時に fixedDays / assignments を掃除

### P2: データ保護（1ヶ月分の作業を守る）
