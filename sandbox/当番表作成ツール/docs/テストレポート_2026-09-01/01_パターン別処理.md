## 2. FAIL詳細（重大度順・すべて実行で確認済み）

**BUG-1【重大】連続回避スワップパスが「曜日固定」職員を固定枠から追い出す**
- 実測: 固定(月-金)10回×22平日=220機会中、固定枠在籍110・**不在108（49%）**。1日おきの交互パターン（毎日固定→毎日連続扱い→スワップ退去）。src/エラー/の実データはこれで FIXED_MISS 34件（エラーフォルダの由来と推測）。
- 原因: 2パス目（2386〜2443行）。2402行で連続職員を検出し2429〜2432行で `arrB[idx] = swapWith` と退去させるが、除外は**ペアのみ**（2406〜2407行 `if (sObj && sObj.trainingPairId) continue;`）。曜日固定（ハード制約1位）を見ていない。
- 修正案: 2406行の除外条件に「dayBの曜日で当該slotに固定されている職員」を追加: `const isFixedHere = (sObj.fixedDays||[]).some(fd => fd.slotId === slot.id && fd.weekdays.includes(getDayOfWeek(year, month, dayB)));`

**BUG-2【重大】枠ローテーションで、固定枠の処理前に他枠が固定職員を奪う**
- 実測: 固定を月・水のみ（スワップ影響を受けない条件）にすると、90機会中**他枠へ流出23（26%）**。BUG-1と独立に発生。
- 原因: 枠処理順ローテーション（2231〜2232行）で固定枠が後回しの日、先行枠のStep 2候補に固定職員が入る。`getEligibleStaff` のガード（2630〜2641行）は「固定枠に既に入っているか（alreadyFixed）」しか見ず、未処理時点では素通し。他枠に取られた後、固定枠Step 1は2323行 `assignedToday.has()` でスキップ。
- 修正案: 日ループ冒頭で全枠のStep 1（曜日固定確定）を一括実行してから各枠のStep 2を回す。

**BUG-3【重大】スワップパスがペアの片割れを単独投入（ペア分離）**
- 実測: 通常5人+ペア1組・1枠3人で15回実行 → **PAIR_SPLIT 14件**。「ペアは必ずセット」のハード制約違反。
- 原因: 退去側はペア除外（2406〜2407行）だが**投入側が無防備**。2417行の swapCandidates にペア職員が含まれ、2430行 `arrB[idx] = swapWith` は1人分置換のため相手が同伴されない（容量チェックもなし）。
- 修正案: 2417〜2418行のフィルタに `!(c && c.trainingPairId)` を追加（ペアごと投入は2枠分の空き確認が必要になるため除外が安全）。

**BUG-4【中】未充足枠・割り当て不能の無通知**
- 実測: 22セル未充足でも toast なし・結果モーダルに不足記載なし。全員「出さない」でも「0件」の表のみ。SPECの「エラーは即座にわかりやすく」に反する。renderGrid（1947〜1992行）にも未充足セルの強調なし（この行の挙動はコードリーディングによる確認）。
- 修正案: showAssignmentStats（2514行〜）に未充足枠一覧の警告、renderGridで実効人数<requiredCountのセルを赤ハイライト。

**BUG-5【低〜中】枠削除時に staff.fixedDays の参照が残置**
- 実測: エラーデータに存在しない枠IDへの fixedDays 参照が6件（実ユーザーデータで発生済み）。原因は枠削除ハンドラ（784〜793行、789行）が `state.slots` の filter のみで `staff[].fixedDays`/`assignments` を掃除しないこと（コードリーディングで確認）。固定設定が無警告で無効化される。

その他リスク: (a) 月変更→再割り当てで前月分が無警告消滅（Undo 15段・セッション内のみが唯一の救済）。(b) importJSONにペア双方向性バリデーションなし・`syncTrainingPair` はモーダル保存時のみ実行（1417行）— 破損データでのsingleモード枠数計算リスクは推測。(c) 偏差表示2569〜2570行で `-0.0` 時に `+-0.0` 表示の可能性（未実測・コードリーディングのみ）。

## トップ5要約

1. **スワップパスが曜日固定を破壊**（2386〜2443行）— 固定機会の49%で固定枠から退去。エラーフォルダの実データを再現する現象。
2. **ローテーションで固定職員が他枠に流出**（2630〜2641行+2323行）— 独立条件で26%。BUG-1と併発し曜日固定はほぼ信頼できない。
3. **スワップパスがペアを分離して単独投入**（2417〜2432行）— 15回中14件のハード制約違反。
4. **未充足枠の無通知** — 欠員に庶務担当者が気づけない運用リスク。
5. **枠削除で fixedDays 残置**（789行）— 実データで発生済み、固定設定が無警告で無効化。

それ以外（時短・公休・不可日・免除・出さない・同日重複・容量・ペア基本動作・applyMode・境界条件・公平性・登録順バイアス・冪等性・200人性能）はすべて健全であることを実行で確認した。
